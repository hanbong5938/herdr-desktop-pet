# Migrating from v0.1.4 to v0.1.6

[Version documentation](../releases/README.md) · [v0.1.4 notes](../releases/v0.1.4.md) · [v0.1.6 notes](../releases/v0.1.6.md) · [한국어](#한국어)

This guide describes the shipped replacement of the v0.1.4 multiline message composer by v0.1.6 inline-card replies. The same transition applies when moving from v0.1.4 to a later app, but for the current stable v0.2.0 installation and additional behavior also read the [v0.1.11 → v0.2.0 migration](v0.1.11-to-v0.2.0.md) and [stable note](../releases/v0.2.0.md). v0.1.5 was tagged but packaging failed before binary publication; it is not an intermediate binary upgrade. Historical behavior is reconstructed from the [v0.1.4 README](https://github.com/hanbong5938/herdr-desktop-pet/blob/v0.1.4/readme.md) and [v0.1.6 README](https://github.com/hanbong5938/herdr-desktop-pet/blob/v0.1.6/readme.md), not a new execution report.

## Before upgrading

Use the [installation guide](../../readme.md#install-as-a-herdr-plugin-recommended) for plugin, Homebrew, or source installation. Keep the same configuration/profile paths to retain character packs and saved preferences; back up configuration before replacing an app. In-memory reply/dialogue drafts do not survive quitting or restarting: save personal dialogue and handle unsent messages first. This guide does not promise that an older binary can read newer saved data.

The lifecycle switches live exclusively in `lifecycle.json`. Existing boolean `enabled` migrates to `auto_start`, including `false`; a missing `exit_with_herdr` defaults to off for an existing profile. New profiles default both switches on. Endpoint/startup metadata and unrelated fields are preserved; invalid JSON, keys, types, or values report errors rather than resetting the profile, and a failed save retains prior switches and policy. See the [lifecycle guide](../../readme.md#lifecycle-settings).

## Keyboard and card behavior

| Interaction | v0.1.4 composer | v0.1.6+ inline reply |
| --- | --- | --- |
| Open input | Multiline composer in the expanded bubble | Initially hidden, including All; click a local agent session card to open its one-line reply |
| Enter | Insert a newline | Submit, unless IME composition is active |
| Command+Enter / Send | Submit | Submit, unless IME composition is active |
| Escape during IME | Cancel composition first | Cancel composition first; do not submit or fold the reply as the same action |
| Escape without IME | Collapse the bubble | Fold only the reply field; keep the bubble and session draft |
| Click outside bubble | Do not infer the new inline behavior for the old composer | Fold only the reply field, except during IME composition |
| Click elsewhere inside bubble | Old composer layout | Does not automatically fold the reply |
| Newlines | Multiline text | Every committed newline from typing, paste, or text import becomes a space; active marked/preedit text is untouched until committed |

Choosing a different card folds the previous reply and opens the new local card's reply. Remote cards show read-only feedback and have no reply or Send control. During IME composition, card selection, filters, and structural row replacement are deferred without discarding text. When composition ends, only the latest valid target still visible under the current filter/display cap and connection generation is applied. The committed text remains with its original session; live status and send eligibility stay current while navigation waits. The reply follows the final displayed row after insertion/deletion, rather than the previous row geometry.

Per-session drafts stay in memory when the field folds or the bubble collapses, not across app restart. A successful acknowledgement clears and folds only the matching current reply: an edited draft or newly selected reply survives an in-flight send. Failure or unknown delivery preserves the draft and field state. Acknowledged submission is not completed agent processing.

## Sending remains local-only

Only the selected local source's `agent.prompt` API receives prompts; there is no global CLI, shell, SSH, raw-pane input, or remote forwarding fallback. Excluded local sources, offline/stale/unready sessions, unsupported targets, and retained remote cards cannot receive prompts. `unsupported_method` is reported without fallback. Approval/question UI belongs in the real terminal.

Herdr 0.9.0+ is the local observation baseline, not proof of `agent.prompt` support; the original evidence verified that API with Herdr 0.9.2. Unknown delivery must be checked before a manual resend; there is no automatic retry. The API targets the agent currently occupying the pane without an atomic expected-session guard, so a last-instant occupant/session replacement cannot be ruled out. Client-attach auto-start separately requires official Herdr 0.9.3 source with the supplied patch applied and built, or a real host release advertising that hook; stock 0.9.0/0.9.3 and the manifest floor alone are insufficient. Follow the [integration authority](../../integrations/herdr/README.md).

## 한국어

v0.1.4의 여러 줄 메시지 입력창은 v0.1.6부터 카드별 한 줄 답장칸으로 교체되었습니다. 나중 버전으로 옮길 때도 이 변경이 적용되지만 현재 안정판 v0.2.0의 설치·추가 동작은 [v0.1.11 → v0.2.0 업그레이드 안내](v0.1.11-to-v0.2.0.md)와 [안정판 기록](../releases/v0.2.0.md)을 함께 보세요. v0.1.5는 태그만 있고 패키징 실패로 공개 바이너리가 없으므로 중간 바이너리 업그레이드가 아닙니다. 위 안내는 당시 태그의 README를 바탕으로 재구성한 기록이며 새 검증 결과가 아닙니다.

### 업그레이드 전

[한국어 설치 안내](../../readme.ko.md#herdr-플러그인으로-설치-권장)를 따르고 기존 설정·프로필 경로를 유지해 캐릭터 팩과 저장된 환경설정을 보존하세요. 앱 교체 전 설정을 백업하세요. 답장·대사 초안은 메모리에만 남아 종료·재시작 후 사라지므로 대사를 저장하고 미전송 메시지를 먼저 처리하세요. 새 데이터의 구버전 호환성은 보장하지 않습니다.

실행 관리 설정은 `lifecycle.json`만 소유합니다. 기존 boolean `enabled`는 `false`도 유지해 `auto_start`로 옮기고, 기존 프로필에 `exit_with_herdr`가 없으면 꺼짐으로 이전합니다. 새 프로필은 둘 다 켜짐입니다. endpoint·startup·무관한 필드는 유지하며 JSON·키·타입·값 오류는 초기화 대신 오류로 보고합니다. 저장 실패는 이전 스위치와 실행 정책을 유지합니다.

### 입력 동작 변경

- **v0.1.4:** Enter는 줄바꿈, Command+Enter·보내기는 제출, Escape는 말풍선 접기입니다. 입력기(IME) 조합 중 Escape는 조합부터 취소합니다.
- **v0.1.6 이후:** 답장칸은 전체 보기에서도 처음에는 숨겨져 있고 로컬 에이전트 카드를 눌러 엽니다. 다른 카드를 누르면 이전 답장칸을 접고 새 카드에 엽니다. 원격 카드는 읽기 전용이며 답장칸·보내기 버튼이 없습니다.
- Enter·Command+Enter·보내기로 제출하지만 조합 중에는 제출하지 않습니다. Escape는 조합부터 취소하고, 조합이 없으면 **답장칸만** 접습니다. 말풍선 밖 클릭도 답장칸만 접지만 조합 중에는 접지 않습니다. 말풍선 내부의 다른 곳을 클릭하는 것만으로는 자동으로 접지 않습니다. 말풍선 전체를 접는 동작으로 오해하지 마세요.
- 타이핑·붙여넣기·텍스트 가져오기의 모든 확정 줄바꿈은 공백으로 바꿉니다. 미확정 조합 문자는 확정까지 그대로 유지합니다. 조합 중 카드 선택·필터·행 교체를 보류하고, 끝나면 현재 필터·표시 제한·연결 세대에서 유효하고 보이는 마지막 대상만 적용합니다. 확정 문자는 원래 세션의 초안에 남으며 실시간 상태·전송 가능 여부는 계속 갱신됩니다. 삽입·삭제 후 최종 표시 행에 답장칸을 붙입니다.
- 세션별 초안은 답장칸·말풍선을 접어도 현재 앱 실행 중 유지하지만 재시작 후에는 사라집니다. 접수 성공은 현재 내용과 일치하는 답장만 지우고 접으며, 전송 중 수정한 초안·새 선택은 유지합니다. 실패·전달 불명은 초안과 답장칸 상태를 보존합니다. 접수는 에이전트 처리 완료가 아닙니다.

### 전송 안전

선택한 로컬 소스의 `agent.prompt`로만 제출합니다. 전역 CLI·셸·SSH·패널 직접 입력·원격 머신 전달로 우회하지 않습니다. 관찰 제외·오프라인·오래된 세션·준비되지 않은 대상·지원 불가 서버·남아 있는 원격 카드는 전송할 수 없습니다. `unsupported_method`는 우회 없이 보고하며 승인·질문은 실제 터미널에서 처리하세요. 로컬 관찰 기준 Herdr 0.9.0만으로 이 API 지원은 보장되지 않으며 원래 기록은 0.9.2에서의 확인입니다. 전달 불명은 재전송 전에 확인해야 하고 자동 재시도는 없습니다. 예상 세션을 원자적으로 검증하는 API가 아니므로 제출 순간 패널의 에이전트·세션 교체 경합을 배제할 수 없습니다.

client-attach 자동 실행은 별도로 공식 Herdr 0.9.3 소스에 제공된 패치를 적용·빌드한 호스트 또는 실제 훅 지원을 명시한 릴리스가 필요합니다. 순정 0.9.0·0.9.3과 매니페스트 최소 버전만으로는 부족합니다. [호스트 연동 안내](../../integrations/herdr/README.md)를 따르세요.
