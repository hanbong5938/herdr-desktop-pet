## 안정판 v0.2.0 이후 과거 소스 스냅샷

이 예전 프리뷰 소스에는 당시 **미출시** 세션 검색·상태 필터 교집합·기본순/이름순/출처순 정렬과 실행 중 우선이 있었습니다. 이 기능은 현재 준비된 v0.3.0 안정판 소스에 속합니다. 아래의 과거 체크아웃 설치법 대신 [현재 한영 이전 안내](../releases/0.3.md#한국어--v03-계열)를 사용하세요. 검색은 제목·탭/작업 공간/에이전트/출처 이름·작업 디렉터리·대체 이름에 적용하고 ID·소켓 경로는 제외했습니다. GUI 128개 표시 제한 전에 필터링·정렬했으며 숨겨진 답장 초안은 해당 세션에 남았습니다. 검색창 Enter는 보내지 않고 검색·답장 IME 조합 중 구조 변경을 보류하되 상태는 갱신했습니다.

실행 중 우선은 별도 체크박스 대신 정렬 메뉴의 구분선 아래에 있습니다. 기본순/이름순/출처순과 독립적으로 조합하며 닫힌 메뉴에도 두 상태를 표시합니다. 기존 `session_list.sort`·`session_list.running_first` 저장값, 6개 조합, 기본값과 저장 실패 동작은 그대로이므로 환경설정 이전은 필요하지 않습니다.

당시 미출시 소스의 네이티브 자동화·충돌 인식 초안도 이제 준비된 v0.3.0 소스에 포함되지만 과거 공개 v0.2.0/v0.2.1 바이너리에 소급 적용되지 않습니다. 옛 프리뷰는 `--source` 빌드와 실행 파일 확인이 필요했고 당시 소스/공개 바이너리의 버전이 둘 다 `0.2.0`일 수 있었습니다. 현재 설치에는 [v0.3.0 정본 노트](../releases/v0.3.0.md), [한영 이전 안내](../releases/0.3.md#한국어--v03-계열), [CLI 계약](../cli.md#한국어)을 따르세요. 이 과거 버전 문자열은 새 설치 안내가 아닙니다.

## 선택형 수동 베타 테스트

공개된 변경 불가 [`beta/0.2.0-beta.3` 시험판](https://github.com/hanbong5938/herdr-desktop-pet/releases/tag/beta%2F0.2.0-beta.3)과 별도 순환 베타 포뮬러는 현재 안정판 설치가 아닌 과거 macOS 13+ arm64 시험용으로 남아 있으며 물리적 GUI·IME 인증은 아닙니다. beta2는 `9035c11e5acf76a1092ddf3a08d4360eac680495`를 가리켰고 beta1 준비·삭제 관찰은 beta1만의 증거입니다.

```sh
brew install hanbong5938/tap/herdr-desktop-pet-beta
herdr-desktop-pet-beta --version
herdr-desktop-pet-beta start
herdr-desktop-pet-beta status
```

기존 Homebrew 베타 설치는 실행 중인 베타를 **먼저 종료**하고 업그레이드한 뒤 설치된 CLI 버전을 확인하고 새 앱을 시작하세요. `--version`만으로 이미 실행 중인 beta2 데몬이 바뀌지는 않습니다. beta3 시작 전에는 아래와 같이 안정판도 종료하고 공유 프로필을 백업하세요.
격리 프로필은 종료와 시작에 동일한 설정·상태 디렉터리를 사용하세요.

```sh
herdr-desktop-pet-beta stop
brew update && brew upgrade herdr-desktop-pet-beta
herdr-desktop-pet-beta --version
herdr-desktop-pet-beta start
herdr-desktop-pet-beta status
```

베타 포뮬러는 `HerdrDesktopPetBeta.app`을 `/Applications`가 아닌 Homebrew 접두 경로에 설치합니다. 별도 `herdr-desktop-pet-beta --version`은 `0.2.0-beta.3`을 표시합니다. 신규 사용자는 위 설치 명령을, 기존 사용자는 지금 `brew update && brew upgrade herdr-desktop-pet-beta`를 사용하세요. 베타만 제거하려면 `brew uninstall herdr-desktop-pet-beta`를 사용하세요. 수동으로 사용하려면 연결된 beta3 릴리스에서 공개된 `HerdrDesktopPet-v0.2.0-beta.3-macos-arm64.tar.gz`와 `.sha256`(또는 `SHA256SUMS`)을 받으세요. 압축 해제 전 아카이브 SHA-256 `14bf452aa492fa520a4979ca3e18711e505c52c178c1e1e2edb355b2b07b0920`을 검증하고 `HerdrDesktopPetBeta.app` 또는 포함된 `Contents/MacOS/herdr-desktop-pet` CLI를 실행하세요. ad-hoc 서명·미공증이므로 Gatekeeper 승인이 필요할 수 있습니다.

아래는 beta1과 별개의 **과거 beta2만의 증거**이며 beta3 공개·설치 증거가 아닙니다. 익명 다운로드한 beta2 압축 파일 SHA-256 `ddb61fa2ff45aa0fcc603c175423667512b7fa043461b6ab5e9f2c37576a6432`는 공개 체크섬 및 GitHub digest에 일치했고 앱은 엄격한 서명·버전·arm64·패키지 트리 검증을 통과했습니다. 격리된 beta1 → beta2 업그레이드와 beta2 신규 설치·테스트를 통과했고 압축 해제 앱과 업그레이드 beta2는 분리된 설정·상태와 순정 Herdr 0.9.3에서 UI/제어/등록/데이터 준비 상태에 도달했습니다. 이전 소스 AppKit 배치·입력창 확인은 물리적 키보드·IME·이미지 선택·확인 창 키·포인터·VoiceOver 검증이 아닙니다.

별도의 **공개 beta3 증거**: 변경 불가한 `beta/0.2.0-beta.3`은 `7f644b10affba45957a52c361d2067439a4f1eeb`를 가리킵니다. 세 공개 자산을 모두 익명 다운로드했으며 20,467,942바이트 아카이브 SHA-256 `14bf452aa492fa520a4979ca3e18711e505c52c178c1e1e2edb355b2b07b0920`이 받은 체크섬·GitHub digest와 일치했습니다. 압축 해제 앱의 arm64·버전·엄격한 서명·리소스 트리 검증을 통과했습니다. 실제 공개 베타 전용 tap 포뮬러로 beta2 → beta3 업그레이드와 beta3 신규 설치·각각의 `brew test`를 통과했고 안정판 포뮬러·설치는 그대로였습니다. 압축 해제 앱과 업그레이드한 beta3 앱은 순정 Herdr 0.9.3에서 UI/제어/등록/데이터 준비 상태에 도달했습니다. 사설 pasteboard를 사용한 production ComposerView/BubblePanel AppKit 시험에서 Command-A/C/X/V, 한글·이모지·CRLF 붙여넣기, UTF-16 선택 대체, 포커스 및 추가 modifier·조합 입력 보호를 확인했고 사용자 클립보드는 건드리지 않았습니다. 시험용 파일·훅은 최종 production 검증 전에 제거했습니다. 물리적 키보드·IME·이미지 선택·확인 창 키·포인터·VoiceOver 검증은 아닙니다.

beta3 시험 당시 별도의 베타 포뮬러는 당시 v0.1.11 안정판 설치기·포뮬러를 바꾸지 않았습니다. 이는 **과거 사실**이며 현재 `main`·고정 설치기·안정판 릴리스 계약은 v0.2.0을 대상으로 합니다. 베타 포뮬러·변경 불가 자산은 별도입니다. beta3을 얻으려고 안정판 기본/`--prebuilt` 설치기를 사용하지 마세요. **beta3 → 안정판 v0.2.0**에는 베타 종료·프로필 백업 뒤 **안정판 포뮬러**를 설치/업그레이드하고 안정판 데몬의 `app_version`·실행 파일을 확인하세요. [안정판 이전 안내](v0.1.11-to-v0.2.0.md#한국어)를 참고하세요. 아래 수동 베타 점검표는 과거 기록이며 안정판 검증이 아닙니다.

과거 베타를 안정판과 비교 실행할 때에는 설정과 상태를 **둘 다** 격리하지 않으면 먼저 안정판을 종료하세요. 두 앱은 프로필·제어 네임스페이스를 공유합니다. `preferences.json`, `lifecycle.json`, `characters/`, 관리되는 `menu-bar-icons/` 및 상태를 백업하고, 되돌릴 때 베타를 종료한 뒤 해당 이전 백업을 복원하세요. 하위 버전 호환성은 보장되지 않습니다.

실제 GUI 점검표: (1) 입력창의 IME 조합·확정 초안·선택 위치·키보드 포커스를 캐릭터 숨김/표시, 독립 말풍선 배치·재부착·초기화 및 보류 위치보다 늦은 초기화 상황에서 확인하세요. (2) **폐기 가능한 연결 워크트리만** 사용하여 처음 상태와 Tab으로 **삭제 버튼에 포커스를 둔 상태**에서 Return·숫자 키패드 Enter·Escape 취소를 각각 확인하세요. 취소 시 요청 0건과 별도의 의도적 버튼 실행 결과를 실제 서버·파일 상태에서 확인하세요. 삭제는 무시된 파일을 지우고 프로세스 종료나 패널/작업공간에 영향을 줄 수 있으므로 중요한 체크아웃에는 절대 사용하지 마세요. (3) 이미지 선택 취소·유효/손상 PNG·원본 삭제 후 재시작·기본 아이콘 복원·알 수 없는 환경설정 필드 보존을 확인하세요. 이는 남은 실제 UI 점검이지 자동 검증 통과 주장이 아닙니다.

실제 답장창에서 키보드 포커스·IME 조합·사용자 클립보드 동작을 포함한 Command-A/C/X/V도 직접 점검하세요. 위 사설 pasteboard 프로그램 시험으로 대신할 수 없습니다.

## 기존 프로필 보존

기존 `HERDR_PLUGIN_CONFIG_DIR` / `HERDR_PLUGIN_STATE_DIR` 또는 같은 Herdr XDG 플러그인 프로필을 사용하세요. 앱 교체 전에 설정을 백업하세요. `lifecycle.json`, `preferences.json`, `characters/`를 유지하며 업그레이드 때문에 삭제·재생성하지 마세요. 저장된 캐릭터 선택·가져온 리비전·사용자 대사는 기존 저장소에 남습니다. 재시작 후에는 저장한 대사만 유지되며 답장·편집기 초안은 현재 실행의 메모리에만 남습니다. 실행 관리 설정은 `lifecycle.json`만 소유하며 예전 `enabled`를 `false`도 유지해 `auto_start`로 옮깁니다. 기존 프로필에 `exit_with_herdr`가 없으면 꺼짐으로 이전하고 새 프로필은 둘 다 켜짐입니다. endpoint·startup·무관한 필드와 알 수 없는 환경 설정 키를 보존하며 잘못된 설정은 오류로 보고합니다. 저장 실패는 이전 스위치·실행 정책을 유지하고 프로필을 초기화하지 않습니다. 외부 `--assets` 대사는 활성화 시 정규화한 경로 키를 사용하며 재시작 시 폴더 이름을 바꿔도 기존 키를 자동 이전하지 않습니다.

`preferences.json`, `lifecycle.json`, `characters/`와 함께 같은 설정 디렉터리의 `menu-bar-icons/`도 백업하세요. `menu_bar_icon.asset`이 관리 이미지 사본을 가리킬 수 있어 JSON만 백업하면 그림이 누락됩니다. 과거 프리뷰뿐 아니라 안정판 v0.2.0에도 해당합니다.

과거 소스 프리뷰는 변경이 이미 들어 있는 체크아웃에서만 `bash scripts/install.sh --source`를 사용했고 로컬 커밋을 가져오지는 않았습니다. **현재 v0.2.0 사용자에게 이 절차는 필요하지 않습니다.** 안정판 `main`에는 해당 네이티브 묶음이 있고 기본/`--prebuilt`는 안정판 v0.2.0을 고정하며 `--source`는 현재 보유한 체크아웃만 빌드합니다. 이 과거 방법 대신 [현재 소스 설치](../../readme.ko.md#이-체크아웃-설치-소스-빌드)와 [안정판 이전](v0.1.11-to-v0.2.0.md#한국어)을 참고하세요. 프리뷰에서 네이티브 액션 ID·팩 형식은 유지됐으며 원격 플러그인 자동 설치·SSH 전송 변경은 없습니다.

## 표시 상태는 독립적이며 실행 관리가 아님

| 캐릭터 | 말풍선 | 과거 프리뷰·안정판 v0.2.0 결과 |
| --- | --- | --- |
| 표시 | 표시 | 캐릭터에 부착된 말풍선 |
| 표시 | 숨김 | 캐릭터만 표시 |
| 숨김 | 표시 | 꼬리 없는 이동 가능한 단독 말풍선, 세션 카드·답장 사용 가능 |
| 숨김 | 숨김 | 창은 없지만 앱·세션은 계속 실행, 복구 아이콘 사용 가능 |

`show` / `hide` / `toggle`은 캐릭터만 표시·숨김합니다. 말풍선은 `show_bubble` / `hide_bubble` 또는 **말풍선 → 말풍선 표시 여부**로 별도 제어합니다. 캐릭터를 숨겨도 켜진 말풍선은 숨기지 않습니다. 저장된 단독 위치가 없으면 최초 분리 위치는 계산만 한 위치가 아니라 **실제로 적용된 마지막 부착 말풍선 본문**에서 가져오며 캐릭터 좌표로 대체하지 않습니다. 저장된 단독 위치는 다음 분리 때 우선하며 미확정 문자가 있어도 같습니다. 캐릭터를 표시하면 다시 부착하고 단독 배경 드래그는 말풍선만 움직입니다. 작은 보기·펼친 보기와 답장 재배치는 화면 범위 조정이 필요한 경우 외에는 위치를 유지하며 디스플레이 제거·배치 변경 시 화면 밖 말풍선을 남은 화면으로 복구합니다.

현재 실행에서 캐릭터 숨김·표시를 바꿔도 카드 선택·보기/답장 상태·초안은 유지하며 초안은 재시작 후 사라집니다. 미확정 문자가 있으면 숨김·표시·배치·초기화 중 단독 위치 저장을 조합 종료까지 보류하며 최신 장면과 이후의 초기화가 오래된 보류 위치보다 우선합니다. 단독 상태에서 바꾼 배치 설정은 다시 부착할 때 적용합니다. `reset`은 두 표시 설정을 바꾸지 않고 캐릭터 위치를 초기화하며 단독 위치를 지우거나 실제 새 부착 배치에서 다시 설정합니다. 저장된 위치도 사용 가능한 부착 위치도 없으면 일반 부착 배치를 대체 위치로 계산하며 캐릭터 좌표를 단독 위치에 복사하지 않습니다. **대화창 닫기**는 말풍선만 숨기고 앱·캐릭터·세션과 실행 중 초안을 유지하며 말풍선 표시 설정을 저장합니다. 격리된 실제 AppKit 입력창의 `setMarkedText`/`unmarkText` 콜백에서 조합 문자·확정 초안·선택 위치가 숨김·배치·초기화를 거쳐 유지됐고, 조합 중 부착 창·입력창 프레임은 바뀌지 않았으며 조합 종료 뒤 단독 위치가 저장됐습니다. 물리적 IME·실제 포커스·드래그·화면 배치 검증은 아닙니다.

전체 창 클릭 통과는 두 창 모두에 적용되어 단독 말풍선·인라인 답장도 조작할 수 없습니다. 투명 영역 클릭 통과는 캐릭터 그림에만 적용되고 말풍선은 조작 가능합니다. 포인터 폴링 방식의 클릭 전달 경합이 허용되지 않으면 투명 영역 클릭 통과를 끄세요.

## beta3·안정판 v0.2.0: 답장 글자 잘림 수정

변경 불가 `beta/0.2.0-beta.1`과 과거 포뮬러에는 답장 글자 잘림이 있습니다. beta2는 글자 잘림과 잘못된 링크 스캐너를 고쳤으나 네이티브 답장 클립보드 연결은 없었고 beta3은 이를 추가했습니다. 이 수정은 안정판 v0.2.0 `main`에도 있으며 아래 베타 공개·측정은 안정판 릴리스 증거가 아닙니다.

답장 입력창은 네이티브 텍스트 한 줄과 테두리·스크롤러 공간을 함께 확보하고 그 높이를 답장 행·선택 카드·말풍선에 전달합니다. 문서 폭은 긴 글을 짧게 바꾸거나 비울 때도 현재 텍스트를 따라 줄어들며, 초안·선택을 다시 쓰지 않고 유효하지 않은 가로 스크롤 위치만 제한합니다. 조합 중에는 앱의 배치 변경을 보류하고, 짧은 화면에서는 선택 답장·주 메시지가 들어갈 수 있는 경우 여백부터 줄여 글자 공간을 확보합니다.

자체 Herdr 0.9.3 백엔드·대기 중인 OMP 세션에 연결한 서명된 격리 실제 앱에서 보고된 초안의 Legacy 입력창 외부/내부 clip/문서 높이는 22/3/5 pt에서 43/24/24 pt로 바뀌었습니다. 16 pt 텍스트 줄이 네이티브 창 raster에서 보이고 상위 뷰의 clipping 범위 안에도 들어왔습니다. production 숨김·표시·초기화·배치 콜백에서 동일 입력창·초안·UTF-16 선택 범위·affinity가 유지됐고 네이티브 `insertText`로 선택 영역을 대체했습니다. marked/unmark 콜백에서도 조합·편집 상태를 유지했으며 실제 Overlay 스타일에서도 글자 공간을 확보했습니다. **프로세스 내부의 가상 260 pt 화면 높이 fixture**에서도 선택 답장과 주 메시지가 보였고 이후 원래 화면 구현을 복원했습니다. 물리적 모니터·키보드·IME·활성 포커스의 증거는 아닙니다.

메인 스레드 AppKit 회귀 검증은 production 배치 구현으로 두 스크롤러 스타일, 95/220/390 pt 폭, 빈/짧은/긴 한글·영문·이모지, 긴 글 → 짧은 글/빈 글, 가로 이동, 재부착, 선택 대체, 조합 상태를 확인합니다. 실제 AppKit 디스플레이가 있는 macOS GUI 세션에서 `cargo test --release --target aarch64-apple-darwin --manifest-path native/Cargo.toml --test composer_layout`로 실행하세요. 수동 GUI 점검은 긴 초안 가운데를 선택하고 캐릭터 숨김/표시·초기화·재배치 후 대체 입력하여 두 macOS 스크롤 막대 설정의 글자·커서 전체 높이, 가로 이동, 실제 IME·키보드 포커스를 확인하세요. 기존 프로필·백업 규칙은 위 안내를 유지합니다.

## 설정과 과거 조건부 복구

캐릭터·대화창 배경·카드 헤더를 우클릭 또는 Control-click하고 **설정…**을 선택하면 동일한 전체 3탭 패널을 엽니다. 텍스트 입력은 네이티브 편집 메뉴를 유지하고 버튼·드롭다운·스크롤바도 기존 네이티브 동작을 유지합니다. 메뉴 취소는 카드 선택·초안을 보존합니다. 입력기 미확정 문자가 있으면 대화창의 **설정…**과 **대화창 닫기**를 비활성화하고 선택 시에도 조합 여부를 다시 확인합니다. 조합을 마친 뒤 메뉴를 다시 여세요. 최신 macOS 활성화 API와 macOS 13 호환 경로를 사용하지만 키보드 포커스 이동 허용 여부는 macOS가 결정합니다.

원래 `bf23ced` 체크아웃의 복구 아이콘은 **두 창 모두 숨김 또는 전체 창 클릭 통과 켜짐**일 때만 표시됐습니다. 일반 상태에서는 메뉴 막대 자리를 차지하지 않았고 단독 말풍선 메뉴에 **캐릭터 표시**가 있었습니다. 이는 과거 동작입니다. beta3과 안정판 v0.2.0은 아래 선택형 모드를 제공하며 기본값은 **항상 표시**입니다.

**캐릭터 표시·조작 복구 / Show and Enable Character**는 캐릭터를 표시하고 전체 창 클릭 통과를 끕니다. 말풍선 표시와 투명 영역 클릭 통과는 그대로 둡니다. 표시 중인 말풍선은 다시 부착하고 숨겨진 말풍선은 숨김을 유지합니다. 전체 초기화가 아닌 일부 설정만 바꾸는 복구입니다. 메뉴의 **설정…**과 **종료**도 사용할 수 있습니다. CLI `show`는 이 복구 액션과 달리 캐릭터 표시만 바꾸고 말풍선을 켜거나 전체 클릭 통과를 끄지 않습니다.

## 이후 로컬/beta3 추가, 현재 안정판 v0.2.0: 메뉴 막대 표시·이미지

기존 3탭 네이티브 설정 패널의 **메뉴 막대 아이콘 / Menu bar icon**에서 **항상 표시 / Always show** (`always`)와 **복구가 필요할 때만 표시 / Only when recovery is needed** (`recovery_only`)를 선택합니다. 기본 그림은 템플릿 발바닥이며 사용자 지정 이미지는 같은 상태 아이템·메뉴에서 그림만 바꿉니다. 신규·기존·원래 조건부 복구 체크아웃의 프로필 모두 `preferences.json`에 `menu_bar_mode`가 없으면 항상 표시가 기본입니다. 프로필을 재생성하지 마세요. 복구 시에만 표시를 명시적으로 선택하면 재시작과 무관한 설정 저장 후에도 유지하며 모르는 환경 설정 키와 다른 설정도 보존합니다. 과거 안정판/베타 바이너리에는 CLI 모드 명령·추가 상태 필드·단축키가 없지만 **이 미출시 체크아웃**은 비공개 제어 소켓을 통해 별도로 `preferences set --menu-bar always|recovery_only`를 제공합니다.

항상 표시에서는 앱 실행 중 아이콘을 유지합니다. 복구 시에만 표시에서는 **캐릭터와 말풍선이 모두 숨겨졌거나 전체 창 클릭 통과가 켜진 경우에만** 아이콘을 표시하며 재시작 후·설정창이 열려 있을 때도 같습니다. 조작 가능한 단독 말풍선이나 투명 영역 클릭 통과만으로는 표시하지 않습니다. 두 모드 모두 **설정… / Settings…**과 **종료 / Quit**를 제공하고 복구가 필요할 때에만 **캐릭터 표시·조작 복구 / Show and Enable Character**를 제공합니다. 복구는 캐릭터를 표시하고 전체 클릭 통과를 끄되 말풍선 표시 여부와 투명 영역 클릭 통과는 유지합니다. 항상 표시에서는 복구 후에도 아이콘을 유지하고 복구 시에만 표시에서는 조건이 사라지면 메뉴가 닫힌 뒤 아이콘을 제거합니다. CLI `show`는 여전히 캐릭터 표시만 바꿉니다.

모드 저장은 창 표시·클릭 통과·위치·초안·실행 관리를 바꾸지 않으며 실패 시 이전 모드·아이콘을 유지합니다. 이 기록의 관찰은 이전 작업본과 beta3에 속하고 **새 v0.2.0 릴리스 검증이 아닙니다**. 물리적 키보드 포커스·IME·이미지 선택·VoiceOver·포인터를 인증하지 않습니다.

**이미지 선택… / Choose image…**으로 정적 PNG(인코딩 최대 4 MiB, 디코딩 후 최대 100만 픽셀)를 가져옵니다. 애니메이션·손상·잘림·완전 투명 이미지는 거부합니다. 원래 색을 유지하고 18 pt 안에 비율에 맞춰 배치하며 템플릿으로 바꾸지 않고 1×/2× Retina 표현을 제공합니다. **기본 아이콘 복원 / Restore default icon**은 템플릿 발바닥 그림을 되돌립니다. 선택적인 `preferences.json`의 `menu_bar_icon.asset`은 설정 디렉터리 `menu-bar-icons/`에 저장된 관리 사본을 가리키므로 외부 원본을 옮기거나 삭제해도 유지됩니다. `menu_bar_icon` 설정이 없으면 기본 발바닥 아이콘을 사용합니다. 가져오기·저장 실패 시 이전 이미지와 설정을 유지합니다. 재시작 시 관리 파일이 없거나 손상되었다면 오류를 표시하며 기본 아이콘을 쓰되 사용자 지정 메타데이터는 보존합니다. 기본 아이콘 복원은 이미지만 바꾸고 `menu_bar_mode`, 캐릭터·말풍선 표시, 클릭 통과, 위치, 초안, 실행 관리는 바꾸지 않습니다. 위처럼 관리 디렉터리를 프로필과 함께 백업하세요.

디코딩 전 모든 PNG 청크(투명도·무시하는 보조 청크·`IEND` 포함)의 CRC와 `IDAT` zlib Adler-32를 검증합니다. 압축 해제된 `IDAT`는 원래 색상 형식·비트 깊이로 계산한 스캔라인 길이 또는 Adam7의 실제 7개 패스 길이를 초과할 수 없습니다. 기존 인코딩 4 MiB·디코딩 후 100만 픽셀 한도와 애니메이션·손상·잘림·완전 투명 이미지 거부 및 원래 색상 표시는 바뀌지 않습니다.

새 관리 파일은 대상 이름이 없을 때만 원자적으로 게시하여 중단 시 새 최종 파일에 두 이름의 하드 링크를 남기지 않으며 기존·안전하지 않은 대상은 덮어쓰지 않습니다. 과거 중단으로 저장된 최종 파일과 앱 소유의 접근 제한된 관리 디렉터리 안의 레거시 `.icon` 임시 파일이 **같은 inode의 링크 수 2인 하드 링크**로 확인된 경우에 한해 **동일한 정상 PNG를 명시적으로 다시 가져오면** 해당 임시 링크를 복구합니다. 시작 시 자동 정리·삭제는 없고 다른 링크·파일은 건드리지 않습니다. 기본 그림·오류로 대체된 경우에도 사용자 지정 메타데이터와 기존 프로필을 보존하며 초기화는 필요하지 않습니다.

과거 **소스 프리뷰/beta3** 격리 확인에서 비공개 관리 PNG의 외부 원본을 삭제하고 재시작해도 선택과 알 수 없는 설정이 유지됐고 실제 상태 버튼의 비템플릿 이미지가 18 pt·18×18/36×36 표현으로 남았습니다. 이는 새 안정판 v0.2.0 검증이나 실제 선택 창·시각·VoiceOver 인증이 아닙니다.
실제 상태 메뉴 동작으로 설정을 연 뒤 활성화된 **기본 아이콘 복원** 버튼에서 AppKit `performClick`으로 production 초기화 콜백을 실행했습니다. 상태 이미지는 템플릿으로 바뀌고 `preferences.json`에서는 `menu_bar_icon`만 제거됐으며 나머지 알려진/알 수 없는 필드는 그대로였고 예전 앱 소유 관리 PNG 링크는 제거됐습니다. 실제 버튼 클릭이나 이미지 선택 취소·정상/손상 PNG 선택·VoiceOver 증거는 아닙니다.

## 이후 로컬/beta3 추가, 현재 안정판 v0.2.0: 연결 워크트리 삭제

이 기능에 새 환경설정·필수 프로필 이전은 없었습니다. 과거 네 묶음 이후 구현되어 beta3에 포함됐고 이제 안정판 v0.2.0 `main`에도 있으며 이전 v0.1.11 바이너리에는 없습니다. 카드 헤더 우클릭/Control-click은 다른 카드가 선택돼 있어도 해당 카드를 대상으로 하며 대화창 배경에서는 메뉴를 열 때 선택한 카드를 대상으로 합니다. 메뉴는 대상을 명시합니다. 적격 로컬 연결 워크트리가 없으면 삭제 항목이 없고 네이티브 텍스트·컨트롤 메뉴는 그대로입니다. **대화창 닫기**는 숨기기만 합니다. 원격 카드와 메인 저장소는 삭제 대상이 아닙니다.

현재 실행 중인 로컬 세션의 유효한 세대에 중복 없이 일치하는 연결 워크트리의 확실한 메타데이터가 있어야 합니다. 이전 서버의 선택적 메타데이터가 없거나 잘못되거나 모호하면 관찰은 유지하되 삭제 항목은 표시하지 않습니다. 메타데이터는 있지만 `worktree.remove`가 지원되지 않으면 우회 없이 미지원 결과를 알립니다. 로컬 관찰 최소 버전이 삭제 지원을 뜻하지는 않습니다. 확인 창에는 저장소·정확한 체크아웃·워크스페이스·영향받는 탭/패널/프로세스·유지되는 브랜치와 **무시된 파일도 삭제됩니다** 경고가 있습니다. `force: false`여도 무시된 파일이 삭제될 수 있으므로 필요한 파일을 미리 백업하세요. 취소가 첫 번째·기본 선택(Return·숫자 키패드 Enter·Escape)이고 삭제가 두 번째입니다. 네이티브 창은 배치 후 취소 버튼 cell을 기본 버튼으로 명시하며 실패 시 삭제를 중단하고, 임시 Escape 처리에서 동일한 취소 동작을 실행한 뒤 확인 창이 닫히면 처리를 제거합니다. 휴지통·되돌리기·브랜치 삭제는 없습니다.

메뉴에서 대상을 고정하고 확인 후 새 스냅샷으로 재검증합니다. IME 조합 중에는 비활성화하고 실행 시 다시 확인하며 한 번에 하나의 작업만 허용합니다. 전용 비동기 `worktree.remove` 요청 하나에 `{workspace_id, force: false}`를 보냅니다. 변경된 tracked/untracked/submodule 파일 및 잠긴 체크아웃은 백엔드가 거부하며 강제하지 않습니다. 셸/git 우회, `force: true`, 자동 신뢰, 낙관적 로컬 삭제, 자동 재시도가 없습니다. 쓰기를 시도한 뒤 전달 여부가 불명확하면 **결과 미확정**으로 취급하고 수동으로 다시 시도하기 전에 체크아웃·워크스페이스를 확인하세요. 실패했다고 단정하거나 자동 재전송하지 않습니다. 행이 없어지거나 선택이 바뀌거나 창을 숨겼다가 다시 열어도 공통 말풍선의 피드백을 유지하며 일반 watcher의 약 5초 갱신이 최종 관찰 기준입니다.

API는 `workspace_id`만 받고 예상 체크아웃이나 세대를 받지 않습니다. 클라이언트의 새 스냅샷 검증은 검증 후 서버 재시작·워크스페이스 재연결을 **원자적으로 막는 CAS가 아닙니다**. 워크트리 API 지원은 아래 별도 패치 호스트가 필요한 client-attach 자동 시작과 독립적입니다. 실제 격리 워크트리 실험은 순정 Herdr 0.9.3에서 수행했으며 로컬 관찰의 0.9.0 기준만으로 삭제 지원을 추론하지 마세요. 네이티브 테스트·빌드 및 실제 백엔드·sender 확인은 [Unreleased 기록](../releases/unreleased.md#현재-작업본-추가-기능-연결된-워크트리-삭제)에 구분해 적었습니다. Window Server 최상위 가림 창 때문에 실제 확인 창 Return·숫자 키패드 Enter·Escape·삭제 버튼 포커스 키 입력, 우클릭, 물리적 IME 입력은 막혔습니다. 설정된 취소 동작을 실제 키 입력 검증으로 해석하거나 화면 잠김 여부를 추정하지 마세요.

## 원격 관찰: 저장된 선택 유지·읽기 전용

**이 Mac**은 기본 켜짐, **원격 머신**은 기본 꺼짐입니다. 오른쪽 정렬 네이티브 스위치는 **관찰할 머신** 아래 저장된 프로필 선택과 별도입니다. 행은 머신 이름·저장된 세션·상태를 구분합니다. 내용에 맞는 행·카드·스크롤 크기로 고정 간격·중복 도움말을 대체하며 불투명한 프로필 ID별 컨트롤 재사용으로 폴링·이름 변경 중 포커스·스크롤을 유지합니다. 목록이 줄면 스크롤 범위를 조정합니다. 레이블·문맥 접근성 이름은 한국어·영어로 제공합니다.

최초 목록 조회·확인된 빈 목록·미선택·일시 중지·확인 중·관찰 중·사용 불가·비활성을 구분합니다. 조회 실패 시 이전 목록을 유지하고 오래된 목록임을 명시합니다. 원격 관찰을 꺼도 선택을 유지하되 이전 성공 상태는 관찰 꺼짐 안내로 가립니다. 머신 등록·이름 변경이 새 프로필을 자동 선택하지 않습니다. 프로필 비활성화·제거는 관찰에서 제외할 뿐 원격 프로세스를 종료하지 않습니다. 모든 관찰을 끄면 알 수 없음 상태입니다. 관찰 스위치는 카드·수·상태·반응을 제어하고 카드 필터는 표시되는 카드만 좁힙니다.

SSH 설정·머신 등록/인증·서버 설정 승인은 [대화형 Herdr 터미널](https://herdr.dev/docs/0.9.2/connecting-machines/)에서 직접 진행하세요. 선택한 활성 프로필은 호스트 전체가 아닌 저장된 원격 세션 하나를 관찰합니다. 원격에는 호환되는 실행 서버가 필요하지만 캐릭터 앱·플러그인은 필요하지 않습니다. 목록 갱신·선택 프로필 조회는 약 5초 간격이고 원격 관찰을 꺼도 목록을 갱신합니다. 짧은 전환은 누락될 수 있습니다. 끊긴 카드의 데이터는 마지막으로 본 오프라인·알 수 없음 데이터이지 실시간 상태가 아닙니다. 복구·재선택 직후 첫 스냅샷은 기준 상태이며 이전 완료 반응을 재생하지 않습니다.

등록 안내와 접힌 진단은 읽기 전용입니다. **재연결 명령 복사**는 프로필 ID를 안전하게 셸 인용한 `herdr machine reconnect '<profile-id>'` 명령을 클립보드에 복사하고 네이티브 피드백을 제공하며 **실행하지 않습니다**. `herdr machine list`로 ID를 확인하고 터미널에서 직접 복구하세요. 앱은 인증을 묻거나 원격 소프트웨어를 설치하거나 SSH 전송을 바꾸거나 원격 실패를 로컬 조회로 대체하지 않습니다. 원격 카드는 관찰 전용이며 머신 전달 경로로 메시지를 보내지 않습니다.

## 원격 전용 시작과 watcher 종료

캐릭터는 **로컬 Mac**에서 실행합니다. 터미널에서 저장 머신을 인증하고 **원격 머신**을 켠 뒤 활성 프로필을 명시적으로 선택하세요. 원격 세션 attach·머신 등록만으로는 관찰하지 않습니다. 아직 정상 로컬 서버가 없다면 선택적으로 **처음 시작 전에** 네이티브 CLI를 사용하세요.

```sh
herdr-desktop-pet settings set exit_with_herdr off
```

소스 설치에서는 설치된 CLI 대신 `./dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet`을 사용할 수 있습니다. 네이티브 설정은 캐릭터가 꺼짐·호스트 없음·플러그인 비활성 상태에서도 동작하고 캐릭터를 실행하지 않습니다. Herdr 플러그인 액션은 실행 중인 활성 호스트가 필요합니다. 원격 조회가 정상화되면 원할 경우 `exit_with_herdr on`으로 다시 켜세요.

**이 Mac 끄기는 로컬 표시 데이터만 제외하며 로컬 endpoint의 실행 관리를 끄지 않습니다.** 최초의 유효한 로컬 `plugin_list`에 desktop-pet이 없는 것은 비활성화가 아닙니다. 로컬 스냅샷·구독·원격 조회를 유지합니다. 명시적 `enabled: false`는 해당 endpoint를 분리합니다. 이 데몬에서 활성 또는 비활성 행을 이전에 본 뒤 사라진 것은 관찰된 연결 해제이므로 분리합니다. 이 이력은 같은 데몬의 재확인·재연결 중 유지되지만 새 데몬에는 이어지지 않습니다.

**등록된 모든 로컬 endpoint에서 비활성화·연결 해제가 확인되면 즉시 종료**하며 정상 원격 조회·`exit_with_herdr` 꺼짐도 예외가 아닙니다. 최초부터 항목이 없음은 이 종료 조건이 아닙니다. 나머지 정상 연결 소실은 종료 설정이 켜졌을 때 기존 30초 유예를 적용하며 최초 서버 없는 시작도 포함합니다. 정상 재연결은 유예를 취소하고 정상 서버 하나가 남으면 종료하지 않습니다. 클라이언트 detach는 서버 소실이 아니며 오래된 endpoint·실패한 재시도는 유예를 늘리지 않습니다. 종료 설정을 끄면 진행 중 유예를 취소하고 단절 중 켜면 새 30초를 시작합니다. Stop·Quit은 현재 실행만 끝내며 자동 시작을 끄지 않으면 다음 조건 충족 이벤트로 재실행할 수 있습니다. 자동 시작 설정 변경 자체는 현재 캐릭터를 종료·표시하지 않습니다.

## 기능 요구 사항을 따로 진단

로컬 관찰은 Herdr 0.9.0 이상을 지원합니다. 원격 조회는 [저장 머신 API 전달](https://herdr.dev/docs/0.9.2/cli-reference/#saved-ssh-machines)을 지원하는 로컬 CLI(`herdr --machine <profile-id> api snapshot`, 0.9.2 문서의 기능)와 호환 원격 서버가 필요합니다. 로컬 답장에는 별도로 `agent.prompt`가 필요하며 원래 기록은 0.9.2에서의 확인이지 관찰 최소 버전을 만족하는 모든 서버의 지원 보장이 아닙니다. 오프라인·오래된 세션·준비되지 않은 대상·미지원 대상은 전송할 수 없습니다. 셸·SSH·패널 입력 우회나 자동 재시도는 없습니다. 전달 불명은 재전송 전에 확인하고 승인·질문은 실제 터미널에서 처리하세요. 예상 세션을 원자적으로 검증하지 않는 API라 제출 순간 패널 대상 교체 가능성이 남습니다.

client-attach 자동 시작은 별도로 공식 Herdr 0.9.3 소스에 [client-attached 패치](../../integrations/herdr/client-attached.patch)를 적용·빌드한 호스트 또는 실제로 훅 지원을 명시한 릴리스가 필요합니다. 순정 0.9.0·0.9.3에는 없으며 manifest 최소 버전은 지원 증거가 아닙니다. [패치된 호스트 안내](../../integrations/herdr/README.md)의 `PATCHED_HERDR`를 사용하고 PATH의 순정 `herdr`로 대신하지 마세요. 연결 경고와 구독 수락을 확인하세요. 이미 실행 중인 서버에 플러그인을 연결·활성화만 해서는 캐릭터가 실행되지 않으며 한 번 시작하거나 다음 조건 충족 attach를 기다려야 합니다.

`Herdr watchers are shutting down`이면 상속된 `HERDR_SOCKET_PATH` / `HERDR_CLIENT_SOCKET_PATH`, PATH의 CLI 파일·버전, 해당 소켓을 제공하는 서버를 따로 확인하세요. 다른 서버의 플러그인 목록은 데몬이 관찰한 endpoint의 진단이 아닙니다. 원하는 CLI·소켓·세션을 함께 확인하고 원격 프로필·전달 CLI 버전도 점검하세요. 패치된 호스트가 어느 서버에도 desktop-pet을 설치해 주지는 않습니다.
