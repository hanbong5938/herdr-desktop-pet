# Upgrade from v0.1.11 or beta3 to stable v0.2.0

[한국어](#한국어) · [English README](../../readme.md) · [v0.2.0 notes](../releases/v0.2.0.md) · [Release catalog](https://github.com/hanbong5938/herdr-desktop-pet/releases/tag/v0.2.0)

At the time of this v0.1.11/beta3 → v0.2.0 transition, stable v0.2.0 was the `main` source and default/prebuilt installer target on Apple Silicon macOS 13+; for the **current** source and installation target, see the [root installation guide](../../readme.md). Its package is `HerdrDesktopPet.app`, with `herdr-desktop-pet` CLI; the release contract names `HerdrDesktopPet-v0.2.0-macos-arm64.tar.gz`, its `.sha256`, and `SHA256SUMS`. Check the release catalog for actual asset publication before relying on prebuilt installation. The native v0.2.0 feature set includes independent character/bubble visibility, standalone bubble, configurable menu-bar icon (Always/Activity/Hidden), and worktree removal.

## Prepare and preserve your profile

Quit or stop the **running** old stable or beta daemon before starting the new one. `start` can reuse the old running daemon even after installing a new CLI; `--version` alone does not show which daemon owns the control socket. If a plugin host is configured to auto-start the pet, stop it for the upgrade and prevent a qualifying host startup/attach from relaunching it while replacing the app. Use the same config and state directories to stop the daemon you intend to replace.

Back up the actual Herdr plugin configuration and state directories (default Herdr XDG plugin paths, or your `HERDR_PLUGIN_CONFIG_DIR` and `HERDR_PLUGIN_STATE_DIR`) before replacement. Include **both directories**: `preferences.json`, `lifecycle.json`, `characters/`, managed `menu-bar-icons/`, and state such as the control socket/log. The image preference may point to a file under `menu-bar-icons/`; copying only JSON does not save that image. Keep the backup outside the live profile. Retain your saved character packs, dialogue, and lifecycle settings; do not delete/recreate the profile as part of an upgrade. Unsaved reply/editor drafts exist only in memory. The new profile's menu-bar mode defaults to Always show when `menu_bar_mode` is missing, including for a former conditional-icon preview; explicitly choose recovery-only if desired. No forced profile migration or downgrade compatibility is promised.

Stable and beta normally share **both profile and control namespace**. Do not run them concurrently on shared directories. To run concurrently for an intentional comparison, isolate **both** configuration and state directories for each process with `--config-dir` and `--state-dir` (or correctly injected environment paths, which take precedence). Keep the corresponding paths consistent across stop/start/status. An isolated CLI version check does not imply the other daemon is stopped.

## Stable Homebrew install and upgrade

New installation (after checking the release assets):

```sh
brew install hanbong5938/tap/herdr-desktop-pet
herdr-desktop-pet --version
herdr-desktop-pet start
herdr-desktop-pet status
```

Existing stable v0.1.11 **formula** installation:

```sh
herdr-desktop-pet stop
brew update && brew upgrade herdr-desktop-pet
herdr-desktop-pet --version
herdr-desktop-pet start
herdr-desktop-pet status
```

If Homebrew refuses to load the tap formula, use **formula-scoped trust**, not broad trust: `brew trust --formula hanbong5938/tap/herdr-desktop-pet`, then retry the install/upgrade. Confirm `--version` is `0.2.0`; after starting, confirm `status` shows `app_version` `0.2.0` and the **running executable** is the stable v0.2.0 `herdr-desktop-pet`, not a prior stable/beta path. Stop the running daemon and investigate profile/socket/`PATH` mismatches if they disagree. The formula places `HerdrDesktopPet.app` inside Homebrew's prefix, **not** `/Applications`. It installs only the native app and CLI, not the Herdr plugin or patched host. A previous cask copied an app to `/Applications`: stop that app, then `brew uninstall --cask herdr-desktop-pet` before installing the formula; uninstall does not intentionally erase the user profile.

For an existing **beta3** user, stop the beta daemon on its current shared profile first, back up the profile, then use the **stable** formula commands above. If stable is not yet installed, run `brew install hanbong5938/tap/herdr-desktop-pet`; if already installed, stop its old daemon and run `brew update && brew upgrade herdr-desktop-pet`. **Do not** use `brew upgrade herdr-desktop-pet-beta` to migrate to stable; that updates the separate `HerdrDesktopPetBeta.app` / `herdr-desktop-pet-beta` channel. Leave historical beta artifacts alone. The stable status executable and `app_version`, not the beta CLI's version, confirm the transition.

For this historical v0.2.0 transition, the plugin installer on `main` pinned v0.2.0; this is not a statement about the [current root installation instructions](../../readme.md#install-as-a-herdr-plugin-recommended). Normal plugin installation downloads that verified release into the plugin directory and may fall back to a source build when unavailable or invalid; `bash scripts/install.sh --prebuilt` never falls back, while `--source` builds **the checkout you have** and does not fetch missing feature groups. An app-only Homebrew install does not register the plugin. Linking a development checkout with Herdr requires a separate source build; see the [source guide](../../readme.md#install-this-checkout-from-source). For a manual archive, obtain the stable release asset and checksum from the release catalog and verify against the **published stable** SHA-256 before running the app/CLI; do not reuse beta3's checksum or rename its assets. Browser-downloaded ad-hoc-signed, unnotarized archives may require Gatekeeper approval.

## Rollback and host boundaries

For rollback, first stop the **running v0.2.0 daemon**. Restore the pre-upgrade backup of **both** profile directories before running the older stable or beta executable, and install/use that older channel's actual published binary if needed; do not assume it can read new profile data. Avoid running old and new executables against the same live control namespace. Downgrading without a compatible backup is not guaranteed. If no pre-upgrade backup exists, preserve the current data and inspect it rather than deleting it to suppress errors.

Local observation supports Herdr 0.9.0+, but this minimum does **not** guarantee other APIs. Client-attach auto-start separately requires official Herdr 0.9.3 built with the [supplied client-attach patch](../../integrations/herdr/client-attached.patch), or an actual host release advertising `client.attached`; stock Herdr 0.9.0/0.9.3 do not have that hook. Inspect plugin-link warnings and accepted subscriptions. Local reply submission requires host `agent.prompt` (observed with 0.9.2, not promised by the observation floor), and remote read-only observation needs a local CLI with saved-machine API forwarding plus a compatible running remote server. A local observation minimum or one stock 0.9.3 observation does not prove `worktree.remove` exists on the actual server. An unsupported worktree method has no shell/Git/SSH fallback. The native app runs on the Mac whose **desktop** you intend to display; SSH execution on a remote Mac does not display windows on your local desktop. Remote saved machines supply observations only, not an app GUI or remote prompt delivery.

Worktree removal is destructive: confirm the exact linked checkout and **whole workspace** in the dialog. It closes tabs/panes and terminates processes/agents, deletes the checkout **including ignored files**, leaves the branch, and offers no trash/Undo. Use only a disposable linked worktree for manual checks. The app sends one `worktree.remove` with `force: false`, no automatic retry; after uncertain delivery inspect the server and filesystem before manually retrying. The API names `workspace_id` without an atomic expected-checkout/generation comparison, so a client-side fresh check is **not** an atomic guard against server restart or workspace rebinding. Confirm actual server capability and metadata rather than assuming it from a version floor.

IME marked text defers navigation/layout changes, and the app avoids submission during composition, but programmatic AppKit checks and reported beta3 success do not certify physical keyboard/IME, file picker, alert keys, pointer, or VoiceOver on every machine. Check a real GUI session if those behaviors matter. A wrong-desktop SSH view is not evidence that the local window failed to open. Historical beta evidence is in the [preview record](../releases/unreleased.md); stable release evidence must be recorded separately.

이 v0.1.11/beta3 → v0.2.0 이전 당시 안정판 v0.2.0은 Apple Silicon·macOS 13 이상용 `main` 소스와 기본/사전 빌드 설치 대상이었습니다. **현재** 소스·설치 대상은 [루트 설치 안내](../../readme.ko.md)를 확인하세요. 당시 패키지 이름은 `HerdrDesktopPet.app`, CLI는 `herdr-desktop-pet`이며 릴리스 계약 자산은 `HerdrDesktopPet-v0.2.0-macos-arm64.tar.gz`, 해당 `.sha256`, `SHA256SUMS`입니다. 사전 빌드를 사용하기 전 릴리스 목록에서 실제 자산 공개 여부를 확인하세요. 네이티브 기능은 캐릭터·말풍선 독립 표시와 단독 말풍선, 기본 **항상/활동 시/숨김** 메뉴 막대 아이콘, 워크트리 삭제를 포함합니다.

### 프로필 준비·보존

새 앱을 시작하기 전에 **실행 중인** 이전 안정판 또는 베타 데몬을 종료하세요. 새 CLI를 설치해도 `start`는 기존 데몬을 재사용할 수 있으므로 `--version`만으로 제어 소켓의 실행 앱을 확인할 수 없습니다. 호스트의 자동 시작이 활성화됐다면 교체 중 서버 시작·클라이언트 attach로 예전 앱이 재실행되지 않게 하세요. 종료·시작·상태 확인에는 의도한 데몬과 같은 설정·상태 경로를 사용하세요.

교체 전에 실제 Herdr 플러그인 설정·상태 디렉터리(기본 Herdr XDG 경로 또는 `HERDR_PLUGIN_CONFIG_DIR`·`HERDR_PLUGIN_STATE_DIR`) **둘 다** 라이브 프로필 밖에 백업하세요. `preferences.json`, `lifecycle.json`, `characters/`, 관리되는 `menu-bar-icons/`, 제어 소켓·로그 등이 들어 있는 상태 디렉터리를 포함합니다. 이미지 환경설정이 `menu-bar-icons/`의 사본을 참조할 수 있어 JSON만 복사하면 그림이 누락됩니다. 저장된 캐릭터·대사·실행 관리 설정은 유지하고 업그레이드를 위해 프로필을 삭제·재생성하지 마세요. 저장하지 않은 답장·편집기 초안은 메모리에만 있습니다. `menu_bar_mode`가 없으면 과거 조건부 아이콘 프리뷰 프로필도 새 기본값 **항상 표시**를 사용합니다. 복구 시에만 표시하려면 명시적으로 선택하세요. 강제 프로필 이전이나 다운그레이드 호환성 보장은 없습니다.

안정판과 베타는 보통 **프로필과 제어 네임스페이스를 모두 공유**합니다. 같은 디렉터리로 동시 실행하지 마세요. 의도적인 비교 실행에 한해 **양쪽 프로세스의 설정과 상태 디렉터리를 모두** `--config-dir`·`--state-dir`로 격리하세요(주입된 환경변수 경로가 우선). 종료·시작·상태 확인에서 경로를 일치시키세요. CLI 버전만 확인했다고 다른 데몬이 종료된 것은 아닙니다.

### 안정판 Homebrew 설치·업그레이드

신규 설치(릴리스 자산 확인 후):

```sh
brew install hanbong5938/tap/herdr-desktop-pet
herdr-desktop-pet --version
herdr-desktop-pet start
herdr-desktop-pet status
```

기존 안정판 v0.1.11 **포뮬러** 설치:

```sh
herdr-desktop-pet stop
brew update && brew upgrade herdr-desktop-pet
herdr-desktop-pet --version
herdr-desktop-pet start
herdr-desktop-pet status
```

Homebrew가 tap 포뮬러 로딩을 거부할 때만 광범위한 신뢰가 아닌 **포뮬러 한정** `brew trust --formula hanbong5938/tap/herdr-desktop-pet`을 적용한 뒤 설치·업그레이드를 다시 진행하세요. `--version`은 `0.2.0`, 실행 후 `status`의 `app_version`은 `0.2.0`, **실행 파일**은 이전 안정판·베타 경로가 아닌 안정판 v0.2.0이어야 합니다. 다르면 데몬을 종료하고 프로필·소켓·`PATH`의 불일치를 확인하세요. 포뮬러는 앱을 `/Applications` 아닌 Homebrew 접두 경로에 설치하며 Herdr 플러그인이나 패치된 호스트는 설치하지 않습니다. 이전 cask 앱은 `/Applications`에 복사됐습니다. 해당 앱을 종료하고 `brew uninstall --cask herdr-desktop-pet` 후 포뮬러를 설치하세요. 제거는 사용자 프로필을 의도적으로 지우지 않습니다.

기존 **beta3** 사용자는 공유 프로필의 베타 데몬을 먼저 종료하고 백업한 다음 위의 **안정판** 포뮬러를 사용하세요. 안정판이 없다면 `brew install hanbong5938/tap/herdr-desktop-pet`, 이미 설치돼 있다면 기존 안정판 데몬도 종료한 뒤 `brew update && brew upgrade herdr-desktop-pet`을 실행합니다. **`brew upgrade herdr-desktop-pet-beta`는 안정판 이전 명령이 아닙니다.** 이 명령은 별도 `HerdrDesktopPetBeta.app`·`herdr-desktop-pet-beta` 채널만 갱신합니다. 과거 베타 자산은 그대로 두세요. 베타 CLI 버전이 아닌 안정판 `status`의 실행 파일·`app_version`으로 이전을 확인하세요.

이 과거 v0.2.0 이전 당시 `main` 플러그인 매니페스트는 v0.2.0을 고정했습니다. 이는 [현재 루트 설치 안내](../../readme.ko.md#herdr-플러그인으로-설치-권장)의 버전 설명이 아닙니다. 기본 플러그인 설치는 검증된 릴리스를 플러그인 디렉터리에 받으며 사용할 수 없거나 유효하지 않으면 소스 빌드로 전환할 수 있습니다. `bash scripts/install.sh --prebuilt`는 전환하지 않고 `--source`는 **현재 보유한 체크아웃만** 빌드하며 빠진 기능을 가져오지 않습니다. Homebrew 앱만 설치해도 플러그인이 등록되지는 않습니다. 개발 체크아웃 연결에는 별도 빌드가 필요합니다. [소스 설치 안내](../../readme.ko.md#이-체크아웃-설치-소스-빌드)를 참고하세요. 수동 아카이브는 릴리스 목록의 안정판 자산·체크섬을 받아 **공개된 안정판** SHA-256으로 검증한 뒤 앱/CLI를 실행하세요. beta3 체크섬을 재사용하거나 자산 이름을 바꾸지 마세요. 브라우저로 받은 ad-hoc 서명·미공증 아카이브는 Gatekeeper 승인이 필요할 수 있습니다.

### 되돌리기·호스트 경계

되돌릴 때는 **실행 중인 v0.2.0 데몬을 먼저 종료**하고 이전 버전에서 백업한 **설정·상태 디렉터리 둘 다** 복원한 뒤 이전 안정판/베타 채널의 실제 공개 바이너리를 실행하세요. 새 프로필을 구버전 앱이 읽을 수 있다고 가정하지 마세요. 같은 라이브 제어 네임스페이스에서 신·구 앱을 함께 실행하지 마세요. 호환 백업 없는 다운그레이드는 보장하지 않습니다. 사전 백업이 없다면 오류를 숨기려고 데이터를 삭제하지 말고 현재 데이터를 보존해 조사하세요.

로컬 관찰은 Herdr 0.9.0 이상에서 가능하지만 이 최소 버전이 다른 API까지 보장하지는 않습니다. 클라이언트 attach 자동 시작에는 별도로 [제공된 패치](../../integrations/herdr/client-attached.patch)를 적용·빌드한 공식 Herdr 0.9.3 또는 `client.attached` 지원을 실제로 알리는 호스트 릴리스가 필요합니다. 순정 0.9.0·0.9.3에는 훅이 없으므로 플러그인 연결 경고·구독 수락을 확인하세요. 로컬 답장에는 서버의 `agent.prompt`가 필요하며 0.9.2에서 관찰됐다고 관찰 최소 버전 전체에서 보장되지는 않습니다. 읽기 전용 원격 관찰에는 저장 머신 API 전달 CLI와 호환되는 원격 서버가 별도로 필요합니다. 로컬 관찰의 최소 버전이나 순정 0.9.3에서 한 번 관찰한 결과만으로 실제 서버의 `worktree.remove`를 보장하지 않습니다. 미지원 기능에 Git·셸·SSH 우회는 없습니다. 앱은 **화면을 표시할 Mac**에서 실행하세요. SSH로 원격 Mac에서 실행해도 로컬 Mac 화면에 앱 창은 나타나지 않습니다. 원격 머신은 관찰 데이터만 제공하며 앱 GUI나 원격 메시지 전달 수단이 아닙니다.

워크트리 삭제는 파괴적입니다. 확인 창에서 연결 체크아웃의 정확한 경로와 **전체 작업 공간**을 확인하세요. 탭·패널을 닫고 프로세스·에이전트를 종료하며 **무시된 파일까지** 체크아웃을 삭제합니다. 브랜치는 유지되지만 휴지통·실행 취소는 없습니다. 수동 확인은 폐기 가능한 연결 워크트리에서만 하세요. `force: false`인 `worktree.remove` 한 번만 보내며 자동 재시도하지 않습니다. 전달 결과가 불명확하면 수동 재시도 전에 서버·파일 시스템을 확인하세요. API는 예상 체크아웃·generation의 원자적 비교 없이 `workspace_id`만 받으므로 클라이언트의 재검사는 서버 재시작·작업 공간 재연결을 **원자적으로 막지 못합니다**. 버전 최소값 대신 실제 서버 기능·메타데이터를 확인하세요.

IME 조합 중에는 이동·배치 변경을 보류하고 제출을 막지만 AppKit 프로그램 시험과 사용자가 보고한 beta3 성공이 모든 컴퓨터의 물리적 키보드·IME·파일 선택·확인 창 키·포인터·VoiceOver를 인증하는 것은 아닙니다. 필요하다면 실제 GUI 세션에서 확인하세요. SSH로 다른 데스크톱을 본 것은 로컬 창이 열리지 않았다는 증거가 아닙니다. 과거 베타 증거는 [프리뷰 기록](../releases/unreleased.md)에 두고 안정판 릴리스 증거는 별도로 기록해야 합니다.
