## Source development

Building and manually starting the native app from this checkout does **not** require a Herdr plugin, patched host, or client-attach hook. On the supported Apple Silicon Mac, with Rust/Cargo, Bun, Node.js/npm, Xcode Command Line Tools and `codesign` available, build the packaged app; the following manual-start example assumes an existing healthy local Herdr server:

```sh
bash scripts/install.sh --source
./dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet start
./dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet status
```

With an existing local Herdr server, manual `start` can show local session snapshots (Herdr 0.9.0+) without a plugin or host patch; replies separately require that server's `agent.prompt`. Follow the [first connection steps](../readme.md#install-with-homebrew-first-connection) for socket selection and daemon checks, substituting this packaged CLI for the Homebrew command. For a pet without a healthy Herdr server, set `exit_with_herdr off` using that CLI **before** `start`, as in [Pet without Herdr](../readme.md#pet-without-herdr). The default exit behavior is unchanged. The separate host procedure below is **only** for optional managed plugin lifecycle and client-attach auto-start; a stock host does not gain the `client.attached` hook by building the app.

### Local Tern integration (prebuilt consumer route or optional source development)

Consumers now install the shared native app with `brew install hanbong5938/tap/herdr-desktop-pet`, then explicitly install the separate public [tern-desktop-pet plugin](https://github.com/hanbong5938/tern-desktop-pet) with `tern plugin install https://github.com/hanbong5938/tern-desktop-pet`. This prebuilt route needs no Rust/Cargo, Bun, Node.js or source checkout. Plugin installation does not silently download, build or execute the app. For source development, use the source-build procedure above on this checkout; no integration-branch switch is required. Developers can instead link a sibling plugin checkout with `tern plugin link "$PWD/../tern-desktop-pet"`. Follow the [Tern startup and separate config/state profile instructions](usage.md) for either native executable. Existing Brew users use `brew update && brew upgrade hanbong5938/tap/herdr-desktop-pet`; profiles and preferences are preserved.

This checkout also supports Tern directly in the shared native app, without a Herdr server or a second app identity. With the source-packaged executable above, use `./dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet --host tern start` and `./dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet --host tern status` with one consistent profile; `status.observation_mode` must be `tern`. `--host both` enables Herdr and **local** Tern together; `--socket` remains the Herdr socket. Explicit `--host` overrides exact `HERDR_PET_OBSERVATION_MODE=herdr|tern|both`, otherwise default `herdr`. The launch mode cannot be changed by attaching to an existing daemon. Tern-only launch reaches app readiness without Herdr and does not exit for Herdr absence even with `exit_with_herdr` on. The separate Tern plugin is not this app's Herdr plugin; no Tern artwork is implied.

The Tern window plugin uses configured executable and profile paths in its own `window.luau` palette commands; configure them for this source-built CLI and the same private `--config-dir`/`--state-dir` rather than assuming a published binary on `PATH`. Its periodic local `agents:list` snapshot and `process.run` exchange invoke one short-lived helper process per window per interval (1200 ms in this source). The process overhead has **not** been measured. `tern-exchange` is internal bounded stdin/stdout JSON forwarded over the private same-UID control socket (see [CLI contract](cli.md)); Tern does not get a remote watcher. Window/pane identity, instance/epoch/sequence and five-second freshness fence stale or recycled sessions; only live exact-key local sessions can receive one `agents:ask`. `accepted` means the ask may be queued, not delivered to a model or completed; an uncertain offer/result must not be retried automatically. Installed Tern 0.6.1 declarations do not supply a completion event, so `exited` is unknown rather than a completed outcome; there is no PTY fallback.

Current repair contracts: `status.herdr_socket` is the immutable configured UpdateContext path, including Tern-only mode, not evidence of an active Herdr endpoint; no fake registration/socket is needed. Endpoint identity rejects empty/relative paths, accepts equal absolute paths even when endpoint/parent is absent, otherwise compares full canonical aliases or canonical parents plus the same filename, never basename alone. The plugin stores one canonical KV `connection={version=1,executable,config_dir,state_dir}`: validate the whole object and commit once before switching profile/incarnation. Cancel or failure preserves the old connection. Only an absent canonical value permits one-time adoption of the three legacy keys; cleanup follows a successful commit, malformed canonical data never falls back, and external shared-profile commits fence delayed callbacks.

Exchange v1 failures optionally carry only `error_code:binding_required|instance_changed|source_retired|receipt_rejected|rejected`. The first unbound snapshot has no results and receives no command. Loss of the first registration reply recovers with a new window identity on the normal next poll; `source_retired` resets identity without replaying an ask. An exactly bound `receipt_rejected` drops only the reports captured by that request. Requests have a separate 256 KiB JSON bound; the complete encoded reply has a 512 KiB bound **including its trailing LF**. Actual serialization admits a prompt before pending/offer state, with definite TooLarge rejection and no guessed Herdr headroom. A shared 64-source budget covers Herdr and Tern: reclaim only expired offline Tern sources after finalizing pending work, never live/Herdr sources; source IDs are never reused. The control accept loop's existing 100 ms monotonic tick expires freshness at **>=5 seconds**, independently of serial Herdr polling or client I/O.

The 50 ms SDK callback repair divides fresh inventory into four `tern.sleep(0):next` microtasks: tabs, sessions and agents each get their own callback; hosts and panes share the last callback, followed by pure validation. At most two inventory APIs run in one callback (24 ms in the 12 ms/API fixture). Busy/active-work state fences the entire asynchronous exchange by incarnation/profile/phase; final critical local/pane/agent checks use coherent fresh context. Accepted and failed command reports immediately start the existing fresh full-inventory exchange, rather than waiting for the unchanged 1200 ms periodic timer. There is no cached snapshot, ask retry, new protocol or increased native 5-second accepted-receipt deadline. Measured 1 ms timer callback jitter reached 997 ms under desktop load; coarse inventory timer handoffs were removed. A single SDK call or OS preemption remains outside this budget model: there is no indefinite latency guarantee or general process-overhead benchmark.

The request limit is exactly 256 KiB of JSON bytes; an optional framing LF or CRLF does not count. The complete reply limit remains 512 KiB including LF. The previous 411918-byte real CLI request was accepted before this repair and is now rejected before IPC. A healthy Herdr connection denied admission by a full source budget is retained and admitted on its normal next coherent snapshot once capacity permits; its first admitted baseline does not invent historical completion. No extra retry thread or backoff is introduced.

## Native build and signing

After source installation, the native checks are:

```sh
bun run check
bun run test:native
```

Native hit-overlay blending uses typed subexpressions for compatibility with the release runner's Xcode 16.4 Swift compiler. Preserve these type boundaries when changing the overlay; source builds still require Xcode Command Line Tools.

Debug and release native builds require `codesign`. They ad-hoc sign **only** `rig-decode-worker` with `com.apple.security.cs.allow-jit=true` from [`native/rig/RigDecodeWorker.entitlements.plist`](../native/rig/RigDecodeWorker.entitlements.plist). Cargo tracks plist changes to rebuild and re-sign the worker. JavaScriptCore can JIT-compile the trusted decoder bundle, while the main app and native rig library receive **no** JIT entitlement; worker isolation, validation, and resource limits remain. `bun run package:native` reapplies the worker-only entitlement with the selected signing identity and verifies effective entitlements and strict worker/app signatures after outer-app signing. Failure to sign or verify **stops packaging**. Default ad-hoc packaging is local use, not Developer ID signing or notarization.

The rig bridge checks version and seven C layout sizes **before** handing typed asset/token inputs across the Rust/Swift boundary; initial motion remains borrowed sealed bytes copied by the native host, never a path lookup. The Metal renderer prepasses actual eye-white apertures with independent L/R/unsided stencil bits before stable-ordered color drawing in the same encoder. The CPU semantic hit and raster reference use matching ownership; no-white rigs keep their legacy iris rendering. A `RIG_PROBE_FAULTS` probe can run `--eye-stencil-checks --output ABS` to save real-pixel and semantic fixtures; this does not establish the cause of earlier cancelled/disconnected visual observations.

`scripts/build-rig-native.mjs` records bounded source/compiler/output hashes in `native/target/rig-native/release/rig-native.json`; packaging verifies source and output closure, embeds that build record at `Contents/Resources/rig-native-build.json`, preserves the independent update coordinator and checks its protocol/signature, then writes `dist/HerdrDesktopPet.app.rig-native.json` after signing with hashes of **all** deployed `Contents` files. The sidecar stays outside the signed app to avoid a self-hash cycle. The release workflow uploads a separately named `HerdrDesktopPet-v0.3.6-rig-native.json` asset alongside the unchanged app-only archive and its two checksum files; neither updater nor installer needs a new archive layout. Compare sidecar hashes to actual unpacked, post-signing app files before asserting deployed-byte provenance.

## Native localization

Add each new UI message to every catalog rather than translating runtime values, paths, IDs, or pack-owned metadata. Preferences persist the canonical tokens `system|ko|en|zh-Hans|ja`; dialogue overrides accept `ko|en|zh-Hans|ja`, with independent drafts per locale. Keep CLI/patch validation strict while preserving the tolerant fallback for older saved preferences. `system` checks preferred OS languages in order: Japanese tags match case-insensitively; `zh`, explicit Hans and CN/SG regions resolve to Simplified Chinese, but explicit Hant or TW/HK/MO without Hans must be skipped for the next supported language (default English). External catalog metadata remains Korean for `ko` and English fallback for `en`, `zh-Hans` and `ja`; authored dialogue and its fallback belong to each pack.

When changing native text or CLI language contracts, keep the [CLI contract](cli.md), [English](../readme.md), [한국어](../readme.ko.md), [简体中文](../readme.zh-Hans.md) and [日本語](../readme.ja.md) READMEs, and the [English](usage.md), [한국어](usage.ko.md), [简体中文](usage.zh-Hans.md) and [日本語](usage.ja.md) usage guides aligned.
