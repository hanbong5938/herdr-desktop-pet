# Herdr Desktop Pet v0.3.4 release notes

[Versions](README.md) · [0.3 upgrade guidance](0.3.md) · [Development](../development.md)

## English

v0.3.4 selects the stable source/default-prebuilt target after v0.3.3. This reviewed source note is not publication evidence: use the non-draft [GitHub Release catalog](https://github.com/hanbong5938/herdr-desktop-pet/releases) to confirm the arm64 app archive, its individual `.sha256`, `SHA256SUMS` and the separate `HerdrDesktopPet-v0.3.4-rig-native.json` provenance sidecar. The installer still accepts only an `.app` archive; the sidecar is a separate release asset, not an installer input or a member of the archive.

- The native renderer prepares actual eye-white apertures before stable-ordered paint in the same Metal encoder. Independent L/R/unsided stencil ownership blocks an opposite eye's white from revealing an iris. CPU semantic hits and raster reference use the same ownership rules; an authored iris without an applicable white retains legacy visibility. A real-pixel `--eye-stencil-checks --output ABS` probe exercises opposite-eye bleed, whites ordered after iris, reopening, unsided aperture and no-white legacy behavior. This is a fixture-specific correction, **not** a claim that a past cancelled/disconnected run's white-upper-iris artifact has a proven cause or resolution.
- The native rig boundary reports its ABI version and seven C struct sizes before Rust passes typed inputs, including the existing sealed initial-motion byte snapshot. No old path-based motion layout or compatibility shim is restored. The standalone protocol-2 update coordinator, worker-only JIT entitlement, signature checks and installation protections remain part of the app.
- The rig build writes bounded source/compiler/output SHA-256 identities; packaging verifies build inputs and generated outputs, embeds the original record in the app, then writes an external complete deployed-byte hash sidecar **after** app signing. It includes the update coordinator and all `Contents` files without hashing itself into the signed bundle.

Character-pack format v5 and bundled Rubelia `default@0` do not change. Chaerin `chaerin-research` is an **optional downloadable official character pack**, subject to its separate published pack/version, rights notice and actual gallery listing: this release does not silently install it or replace the selected/default character. Its publication authorization is the rights holder's assertion, not independently verified model or commercial licensing.

For an upgrade, stop the running daemon, back up actual config and state (including installed characters and updater records), verify public checksums and installer/formula cutover, then restart and confirm both `--version` and `status` report the expected executable and `app_version: 0.3.4`. A source commit, note, tag, packaged local app or CLI version by itself does not prove a public release, a consumer upgrade, or historical visual causation. Existing v0.3.3 features and protocol-2 update protections remain intact.

### Pre-publication candidate verification

- Locked release Rust gates passed: main app 591 tests plus the FIFO child test, one ignored; standalone coordinator 29 tests. The main-thread AppKit composer exercised actual geometry and native insertion. Bun passed 57 tests; both TypeScript checks, script syntax and release-document validation passed.
- The unchanged-current-main renderer failed the real-Metal sided-open pixel/semantic fixture; the corrected renderer passed all five ownership/order/legacy fixtures. The packaged current-ABI SDK produced 233 actual Chaerin frames: 10 model entries, 3 same-context reentries, all 80 original authored clips and 140 isolated eye/mouth/head controls. Diagnostic motions stayed private and within the unchanged native key limits; no delivered artwork, overrides or authored clips were replaced.
- The packaged v0.3.4 app imported and selected Chaerin in a disposable profile; managed `selected` and `active` restored to `chaerin-research@1` after restart and catalog preparation, with no asset override. All 68 signed deployed-file identities matched the external record; loader paths and the worker-only JIT/protocol-2 boundary were observed. These local results do not assert that a separately built public archive has already passed consumer installation.


## 한국어

v0.3.4는 v0.3.3 이후 안정판 소스·기본/사전 빌드 대상입니다. 이 소스 노트만으로 공개 배포가 증명되지 않습니다. 비초안 [GitHub Release 목록](https://github.com/hanbong5938/herdr-desktop-pet/releases)에서 arm64 앱 압축 파일·개별 `.sha256`·`SHA256SUMS`와 별도 출처 기록 `HerdrDesktopPet-v0.3.4-rig-native.json` 자산을 확인하세요. 설치기는 기존처럼 `.app`만 담긴 압축 파일을 받으며 사이드카는 별도 릴리스 자산이지 압축 파일의 구성원이나 설치기 입력이 아닙니다.

- Metal 렌더러는 실제 흰자 구멍을 같은 인코더에서 색상 그리기 전에 준비하고 L/R/무방향 stencil을 분리해 반대쪽 눈의 흰자가 홍채를 드러내지 못하게 합니다. CPU 의미론적 hit·참조 래스터도 같은 규칙을 사용하고 해당 흰자가 없는 기존 홍채는 그대로 표시합니다. 실제 픽셀 `--eye-stencil-checks --output ABS` fixture에는 눈 간 누출, 홍채 뒤의 흰자, 다시 뜬 눈, 무방향 흰자, 흰자 없는 기존 방식이 포함됩니다. 과거 취소/연결 해제 실행에서 본 흰자 상단 현상의 원인을 입증하거나 해결을 보증하는 주장은 **아닙니다**.
- Rust가 타입 있는 rig 입력을 전달하기 전에 네이티브 ABI 버전·C 구조체 일곱 개의 크기를 비교합니다. 봉인된 초기 motion 바이트 스냅샷과 독립 protocol-2 업데이트 코디네이터·worker 전용 JIT·서명·설치 보호 계약을 유지하며 예전 motion 경로 구조를 되살리지 않습니다.
- rig 빌드는 범위가 제한된 소스/컴파일러/출력 SHA-256을 기록하고 패키징은 입력·생성 출력을 검증한 뒤 원본 기록을 앱에 넣습니다. 앱 서명 **이후** 코디네이터 포함 `Contents` 전체 배포 바이트의 해시를 외부 사이드카에 기록해 번들의 순환 자체 해시를 피합니다.

캐릭터 팩 형식 v5와 내장 루벨리아 `default@0`는 유지됩니다. 채린 `chaerin-research`는 별도 팩 버전·권리 고지·실제 갤러리 게시가 필요한 **선택형 공식 다운로드 팩**이며 자동 설치하거나 기본/선택 캐릭터를 바꾸지 않습니다. 재배포 권한 승인은 권리 보유자의 진술이지 모델·상업 이용 권한의 독립적 검증이 아닙니다.

업그레이드 전 기존 데몬을 종료하고 설치된 캐릭터·업데이트 기록을 포함한 실제 설정/상태를 백업하세요. 공개 체크섬과 설치기/포뮬러 전환을 확인한 다음 재시작해 `--version`과 `status`의 실제 실행 파일·`app_version: 0.3.4`를 함께 확인하세요. 소스 커밋·노트·태그·로컬 앱·CLI 버전만으로 공개 릴리스나 소비자 업그레이드 또는 과거 시각 현상의 원인을 증명할 수 없습니다. v0.3.3의 기능과 protocol-2 업데이트 보호는 유지됩니다.

### 공개 전 후보 검증

- 잠금된 release Rust 검사에서 본체 591개와 FIFO 자식 검사 1개가 통과했고 1개는 기존대로 무시했습니다. 독립 코디네이터 29개, Bun 57개, 두 TypeScript 검사·스크립트 구문·릴리스 문서 검증이 통과했습니다. 메인 스레드 AppKit 대사 편집기의 실제 배치와 네이티브 입력도 실행했습니다.
- 변경 전 현재 main 렌더러는 실제 Metal 좌우 분리 픽셀/의미론 fixture에서 실패했고 수정 후 소유 영역·순서·기존 방식 다섯 fixture가 통과했습니다. 패키징한 최신 ABI SDK로 채린 233프레임(10모델 진입·동일 컨텍스트 재진입 3개·원본 모션 80개·분리된 눈/입/머리 제어 140개)을 캡처하고 검토했습니다. 진단 모션은 비공개 검수 복사본에만 있으며 기존 네이티브 키 제한을 유지하고 배포 원화·오버라이드·원본 모션을 교체하지 않았습니다.
- 임시 프로필의 실제 v0.3.4 앱에서 가져오기·선택·재시작을 수행했고 카탈로그 준비 후 `selected`/`active`가 모두 `chaerin-research@1`로 복원됐으며 에셋 강제 지정은 없었습니다. 서명 뒤 68개 배포 파일의 해시가 외부 기록과 일치했고 로더 경로·worker 전용 JIT·protocol-2 경계를 확인했습니다. 이 로컬 결과는 별도로 빌드할 공개 압축 파일의 소비자 설치 완료를 주장하지 않습니다.
