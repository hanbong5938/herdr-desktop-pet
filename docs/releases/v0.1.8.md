# Herdr Desktop Pet v0.1.8 release notes

v0.1.8 fixes character-menu recovery after pack operations, persistent dialogue-load errors, and session-title consistency during IME composition. These historical notes are reconstructed from the contemporaneous tagged documentation and the [published release](https://github.com/hanbong5938/herdr-desktop-pet/releases/tag/v0.1.8), not from newly executed tests.

## Fixes

- A completed pack operation retains its final UI result even after its status ages out of the bounded service cache. The character menu no longer remains disabled until restart.
- The UI is woken after pack-mutation admission is released, allowing the menu to re-enable as soon as the operation finishes. This does not permit conflicting mutations while work is still pending.
- A failed dialogue metadata load remains visible while the user types. For example, another process holding the character-store lock can produce a transient `Busy` error. Close and reopen the dialogue editor to retry the same character identity after the store becomes available; typing does not silently clear the failed-load notice.
- Session card titles and collision markers are computed against every session during IME composition, matching the normal refresh path instead of only considering displayed rows.
- The orphaned reply-target label and its unused message were removed.

## Upgrading and compatibility

This is an app release, not a new Herdr host release. The manifest pins app version `0.1.8`; `min_herdr_version = "0.9.3"` remains the lifecycle patch baseline, not proof of host feature support.

The distribution supports Apple Silicon macOS 13+. Local observation supports Herdr 0.9.0+; remote observation requires a compatible local saved-machine forwarding CLI (documented in Herdr 0.9.2) and a compatible remote server. Reply submission separately requires the local `agent.prompt` method; the local-observation floor does not guarantee it, and remote cards remain read-only.

Client-attach auto-start requires official Herdr 0.9.3 source with the supplied `client-attached.patch` applied and built, or a future actual host release explicitly advertising that hook. Stock Herdr 0.9.0/0.9.3 do not implement `client.attached`. Inspect plugin-link warnings and confirm subscription acceptance; an unknown-hook warning is not success. Follow the [host integration guide](../../integrations/herdr/README.md) rather than assuming the `herdr` on `PATH` is patched.

Rubelia remains the only bundled character, with the approved waiting illustration and nine independent upper-thigh poses from [v0.1.6](v0.1.6.md). `default@0`, prior published binaries, and existing imported character selections are retained. The bounded catalog-preparation budget still covers all decoder batches plus renderer setup, while individual decoder deadlines and resource quotas remain enforced. App bundles are ad-hoc signed, not Developer ID signed or notarized.

For present-day installation instructions, use the [English guide](../../readme.md) or [Korean guide](../../readme.ko.md); the [tagged README](https://github.com/hanbong5938/herdr-desktop-pet/blob/v0.1.8/readme.md) preserves this release's instructions.

## 한국어 요약

팩 작업이 끝나거나 제한된 상태 캐시에서 밀려나도 최종 결과를 유지하며, 변경 작업 접수가 해제된 뒤 UI를 깨워 캐릭터 메뉴를 다시 사용할 수 있게 했습니다. 대사 메타데이터 불러오기 오류는 타이핑 중에도 남습니다. 저장소 잠금이 풀린 뒤 편집기를 닫았다 다시 열면 같은 캐릭터로 재시도합니다. IME 조합 중에도 모든 세션을 기준으로 카드 제목·동명 구분자를 계산합니다.

앱 버전만 갱신되며 Herdr 호스트 릴리스는 아닙니다. Apple Silicon macOS 13+가 필요합니다. 로컬 관찰은 Herdr 0.9.0+, 원격 관찰은 호환되는 저장 머신 전달 CLI와 원격 서버, 답장 전송은 로컬 `agent.prompt` 지원이 각각 필요합니다. 클라이언트 attach 자동 시작에는 공식 Herdr 0.9.3에 제공된 패치를 적용해 빌드한 호스트가 필요하며, 순정 0.9.3이나 매니페스트의 최소 버전만으로는 보장되지 않습니다. 알 수 없는 훅 경고를 성공으로 간주하지 마세요. `default@0`·가져온 캐릭터 선택과 이전 배포 파일은 유지합니다.
