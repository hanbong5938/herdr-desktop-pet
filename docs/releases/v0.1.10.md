# Herdr Desktop Pet v0.1.10 release notes

v0.1.10 corrects reviewed white-background pockets and contaminated boundaries in the ten-pose Rubelia default. These historical notes are reconstructed from the contemporaneous repair/provenance records, tagged documentation, and the [published release](https://github.com/hanbong5938/herdr-desktop-pet/releases/tag/v0.1.10), not from newly executed rendering or tests.

## Reviewed native artwork corrections

- Remove reviewed hair-gap background and white-contaminated rims in all ten own-pose PSDs, including `writing`'s bent-arm gap and `head-tap`'s hair loop.
- Two `cancelled` forearm-boundary background fragments require a separately reviewed **one-pixel matte**. This narrowly reviewed boundary correction is not permission to remove pale skin or white garments globally.
- Face, clothing, skin interior, expressions, and motion remain unchanged. There is no spatial warp, layer re-bounding-box operation, or new artwork painting.
- Regenerate the menu thumbnail from a corrected native waiting-pose capture.

The [v0.1.9 notes](v0.1.9.md) retain that release's white-fragment limitation. v0.1.10 ships the reviewed correction in a new app release; the published v0.1.9 downloads remain unchanged.

## Immutable sources and guarded cutover

The source-checkout production workflow supports source-bound post-export repair rather than a renderer workaround:

1. Preserve the source inputs and frozen PSDs unchanged. Pose-local replay plans name the frozen PSD's input hash and reviewed layers/pockets; derived outputs are new candidates, not overwrites of source evidence.
2. Keep per-layer source hashes, trimaps, estimated alpha, and corrected rasters. Bind each matte to the frozen PSD's decoded source-layer RGBA. The repair forbids added alpha and checks unchanged layer metadata and every non-selected RGBA pixel, preserving exact RGBA outside the reviewed support.
3. Background fragments stored in hand/forearm boundary layers require explicit layer opt-in and their own source-bound reviewed plan after comparison with the original pose and native layers. This exception does not authorize face, garment, or skin-interior edits.
4. Retain `background-repair.json` as a pack attribution payload and bind its hash in the source record. Regenerate the pack inventory and repeat native validation plus light/dark neutral and animated review before cutover; a clean source matte alone does not prove clean exported native gaps.
5. A derived correction records its **immediate parent's** manifest hash in `backgroundRepair.previousManifestSha256`, separately from historical motion-reference provenance. Cutover validates the candidate first, verifies the currently installed parent's manifest and full file inventory/hashes/sizes, and refuses a stale or changed parent before swapping. The existing motion-reference record is not rewritten to make the new parent fit.
6. Cutover verifies the parent backup before swap, checks that the replacement matches the staged candidate and native content digest, and restores the previous builtin on failure.

These are the recorded workflow protections, not claims that this documentation change ran the authoring pipeline. The exact repair report and frozen implementation are linked below.

## Upgrading, preservation, and limits

`default@0`, Rubelia's manifest identity, and existing imported character selections are preserved. The owner/source/model records and MIT-preserving DAEMONLET skill remain; engines and model weights are not bundled. Artwork-owner approval is separate from external model rights, as detailed in [v0.1.9](v0.1.9.md).

The remaining visual limitation is that some downcast poses differ slightly from the waiting face (`writing`, `failed`, and `bored` in the earlier notes). This release is a reviewed background correction, not a facial redesign or a claim of perfect pose identity.

This is an app release, not a new Herdr host release. Apple Silicon macOS 13+ is required. Local observation supports Herdr 0.9.0+; remote observation requires a compatible saved-machine forwarding CLI (documented in Herdr 0.9.2) and compatible remote server. Replies require the local `agent.prompt` method separately, and remote cards remain read-only.

Client-attach auto-start still requires official Herdr 0.9.3 source with the supplied patch applied and built, or a future actual host release advertising that hook. Stock Herdr 0.9.0/0.9.3 do not implement `client.attached`; a manifest minimum is not evidence of hook support. Inspect link warnings and confirm subscription acceptance using the [host integration guide](../../integrations/herdr/README.md). App bundles remain ad-hoc signed, not Developer ID signed or notarized.

Use the [English guide](../../readme.md) or [Korean guide](../../readme.ko.md) for current installation; the tagged guides preserve this version's instructions. No prior release archive is replaced by these notes.

## 한국어 요약

기본 10포즈의 검토된 흰 배경 조각과 오염된 경계를 수정했습니다. writing의 굽힌 팔 틈·head-tap의 머리카락 고리와 cancelled의 팔뚝 경계 조각 2개를 포함하며, 팔뚝 조각에는 별도로 검토한 1픽셀 매트를 적용합니다. 얼굴·옷·피부 내부·표정·모션은 그대로이고, 공간 왜곡·레이어 경계 재설정·새 그림 그리기는 없습니다.

원본 PSD·소스 입력·레이어별 trimap/alpha·재현 계획을 보존하고, 검토 영역 밖 RGBA를 정확히 유지합니다. 교체 전 기록된 직전 부모의 manifest와 전체 파일 목록·해시·크기를 확인하여 오래되거나 바뀐 부모는 거부하며, 원래 모션 참조 출처를 고쳐 쓰지 않습니다. `default@0`와 가져온 캐릭터 선택, 이전 v0.1.9 배포 파일은 유지합니다. 조금 처진 눈매의 포즈 차이는 남습니다.

Apple Silicon macOS 13+가 필요합니다. 로컬 관찰(0.9.0+)·원격 관찰(호환 CLI/서버)·로컬 답장(`agent.prompt`)의 조건은 각각 별도이며 원격 카드는 읽기 전용입니다. 클라이언트 attach 자동 시작은 공식 Herdr 0.9.3에 제공된 패치를 적용해 빌드한 호스트가 필요합니다. 순정 0.9.3이나 매니페스트 최소 버전만으로 지원을 보장하지 않으므로, 연결 경고와 구독 수락 여부를 확인하세요.
