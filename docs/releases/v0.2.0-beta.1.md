# Herdr Desktop Pet v0.2.0-beta.1 release notes

**Opt-in manual macOS UI test, not a stable release.** App version `0.2.0-beta.1`; tag `beta/0.2.0-beta.1`. Once published, download `HerdrDesktopPet-v0.2.0-beta.1-macos-arm64.tar.gz` and its `.sha256` from the [prerelease page](https://github.com/hanbong5938/herdr-desktop-pet/releases/tag/beta%2F0.2.0-beta.1), verify SHA-256 before extraction, then run `HerdrDesktopPetBeta.app` directly. Requires Apple Silicon and macOS 13+. This test bundle is ad-hoc signed, **not notarized**; Gatekeeper may require explicit approval. Public `main`, stable v0.1.11, latest, Homebrew, manifests in the working copy, and default/`--prebuilt` installation do not switch to beta. Stable `0.2.0` has not shipped.

## Changes

- Watcher/startup: standalone and remote-only observation starts without waiting for a local source; lifecycle policy stays separate from local observation. Client-attach auto-start still requires a separately patched Herdr host: stock 0.9.0/0.9.3 do **not** provide `client.attached`.
- Independent visibility: character and bubble can be hidden separately; a visible bubble detaches as a movable panel and reattaches when the character returns. Full-window click-through affects both windows; alpha click-through affects character artwork only. Standalone origin is saved separately, reset preserves visibility, and active IME composition defers origin updates.
- Observation settings: compact local/remote source controls preserve saved remote selections and keep remote cards read-only.
- Context/recovery: character and bubble context menus open the full Settings panel; the bubble can be closed independently, retaining run-local drafts. Historical conditional rescue behavior is now selectable: **Always show** (default) or **Only when recovery is needed**. Recovery can show/enable the character without changing bubble visibility.
- Menu image: select a static PNG for the menu-bar icon, or restore the default template pawprint. Imported private managed assets persist without the original source; PNG validation checks chunk CRCs, zlib Adler-32 and inflated scanline size. Restore removes only the owned icon choice and asset, preserving unrelated and unknown preferences.
- Linked-worktree removal: only coherent live local linked-worktree cards offer **Remove Worktree…**; main roots, remote, retained, offline, and ambiguous cards do not. Confirmation defaults to Cancel. The client revalidates before one asynchronous `worktree.remove` request with `force: false`, without shell fallback, forced deletion or automatic retry. The request identifies only `workspace_id`, so revalidation is **not** an atomic guarantee against server rebinding. A backend lacking this method reports unsupported rather than silently deleting by another route.
- Four P2 corrections: the alert uses a scoped Escape handler that invokes actual Cancel independently of the default Return button; deferred standalone origin uses saved position or actually applied attached geometry, with the latest scene/reset taking precedence after composition; generated Markdown URLs encode literal parentheses without double-encoding; mixed link/image references preserve link destinations and retarget only images, including nested references and multiline titles. Invalid definitions remain visible as prose, while valid inline destinations/titles are excluded from reference scanning.

## Evidence and outstanding manual checks

TypeScript checks and **42 Bun tests / 301 expectations** passed; native arm64 release check/build and **343 total tests** passed. Scoped UI rustfmt passed; full-workspace formatting still flags four untouched existing files. An isolated real AppKit composer retained marked text, committed draft, selection and stable attached frames; seeded managed-image restart yielded an actual non-template 18 pt status image with 18×18/36×36 representations. Guarded AppKit `performClick` on enabled Restore produced a template image, removed only `menu_bar_icon` with other known/unknown preferences identical, and unlinked the owned asset. Earlier isolated real-backend worktree exercise and native tests are not physical alert interaction. A Window Server shield blocked physical window input: **keyboard focus, real IME, alert Return/keypad Enter/Escape/Delete, picker Cancel/valid/corrupt selection, pointer gestures and VoiceOver remain unverified**. Test these on your own interactive desktop; no claim of GUI completion is made.

The exact shipping archive was extracted independently and its signature and SHA-256 verified. The packaged `0.2.0-beta.1` daemon reached UI/control readiness using only owned configuration/state, retained bubble visibility through actual character hide/show commands, and exported its bundled default pack through a symlinked CLI. This is startup, control and resource-closure evidence, not physical GUI proof.

Before beta start, quit stable and back up the real configuration and state, including `preferences.json`, `lifecycle.json`, `characters/` and managed `menu-bar-icons/`. Unless explicitly isolating configuration **and** state, both apps share profile and control namespace: never run them together. To roll back, quit beta, restore the backup, then restart stable; downgrade compatibility of beta-written data is not guaranteed. For deletion testing use **only a disposable linked worktree**: ignored files may be removed and running processes, panels or workspace state affected. Check cancellation makes zero requests and deliberately confirmed removal targets the intended checkout; never test with a valuable checkout. See the [English migration checklist](https://github.com/hanbong5938/herdr-desktop-pet/blob/beta/0.2.0-beta.1/docs/migrations/unreleased.md) or [Korean checklist](https://github.com/hanbong5938/herdr-desktop-pet/blob/beta/0.2.0-beta.1/docs/migrations/unreleased.ko.md).

### 변경 사항

- watcher/시작: 로컬 소스 없이 독립 실행·원격 전용 관찰을 시작하며 로컬 관찰 설정과 실행 정책을 구분합니다. client-attach 자동 시작은 별도의 패치 호스트가 필요하고 순정 Herdr 0.9.0/0.9.3의 `client.attached`를 가정하지 않습니다.
- 독립 표시: 캐릭터와 말풍선을 각각 숨기고, 말풍선만 보이면 이동 가능한 독립 패널이 됩니다. 전체 창 클릭 통과는 두 창, 알파 클릭 통과는 캐릭터 그림만 적용됩니다. 위치 저장·초기화는 표시 상태와 독립이며 IME 조합 중 위치 확정을 보류합니다.
- 관찰 설정: 간결한 로컬/원격 선택 UI가 원격 저장 선택을 유지하고 원격 카드는 읽기 전용으로 둡니다.
- 문맥 메뉴·복구: 캐릭터·말풍선 메뉴에서 전체 설정을 열고 말풍선만 닫을 수 있습니다. 실행 중 초안은 유지됩니다. 원래 조건부 복구를 **항상 표시**(기본값)/ **복구가 필요할 때만** 모드로 선택하며 말풍선 표시를 바꾸지 않고 캐릭터 조작을 복구합니다.
- 메뉴 막대 PNG: 정적 이미지를 선택하거나 기본 템플릿 아이콘으로 복원합니다. 관리 사본은 외부 원본 삭제 후에도 유지되고 PNG CRC·Adler-32·스캔라인 길이를 검증합니다. 복원은 소유 이미지와 해당 설정만 지우고 나머지 설정을 보존합니다.
- 연결 워크트리 삭제: 현재 유효한 로컬 연결 워크트리에만 제공하며 메인 루트·원격·보관·오프라인·모호한 대상은 제외합니다. 확인 창의 기본값은 취소이고 새 스냅샷 재검사 뒤 `{workspace_id, force: false}` 요청 하나만 비동기로 보냅니다. 셸 우회·강제 삭제·자동 재시도는 없습니다. `workspace_id`만 전달하므로 재검사는 서버 재연결에 대한 원자적 보장이 아니며 미지원 서버는 미지원을 알립니다.
- 네 가지 P2 수정: 확인 창의 범위 한정 Escape 처리가 기본 Return 버튼과 독립적으로 실제 취소 동작을 실행합니다. 보류된 단독 위치는 저장 위치나 실제 적용된 부착 위치를 쓰고 조합 종료 뒤 최신 장면·초기화를 우선합니다. 생성 Markdown URL의 리터럴 괄호만 인코딩하며 중복 인코딩하지 않습니다. 링크/이미지 공유 참조는 중첩·여러 줄 제목에서도 링크 대상을 유지하고 이미지만 바꿉니다. 잘못된 정의는 일반 문장으로 처리하고 정상 인라인 링크의 대상·제목은 참조 스캔에서 제외합니다.

### 확인 근거와 남은 수동 점검

TypeScript 검사, Bun 테스트 **42개/기대값 301개**, 네이티브 arm64 release 검사·빌드·테스트 **합계 343개**가 통과했습니다. UI 범위 rustfmt는 통과했지만 전체 작업공간 포맷은 건드리지 않은 기존 파일 네 개에서 실패합니다. 격리 AppKit의 실제 입력창 콜백은 조합 문자·확정 초안·선택·안정된 부착 프레임을 관찰했습니다. 미리 설치한 관리 PNG의 외부 원본 삭제·재시작 후 실제 상태 이미지는 18 pt 비템플릿이고 18×18/36×36 표현을 가졌습니다. 활성화된 복원 버튼의 AppKit `performClick`으로 템플릿 복원, 다른 알려진/알 수 없는 환경설정 필드 보존, 소유 파일 삭제를 관찰했습니다. 이전 실제 백엔드 삭제 실험과 네이티브 테스트는 물리적 확인 창 시험이 아닙니다. Window Server 가림 창 때문에 **실제 키보드 포커스·IME·확인 창 Return/숫자 키패드 Enter/Escape/Delete·선택 창 취소/유효/손상 PNG·포인터·VoiceOver는 미검증**입니다. 직접 GUI에서 확인해야 하며 GUI 통과 주장은 아닙니다.

실제 배포 압축파일을 별도 경로에 풀어 서명과 SHA-256을 확인했습니다. 패키징된 `0.2.0-beta.1` 데몬은 앱 소유의 격리 설정·상태에서 UI/control 준비를 마쳤고 실제 캐릭터 숨김·표시 명령 중 말풍선 표시를 유지했으며 심볼릭 링크 CLI로 번들 기본 팩을 내보냈습니다. 시작·제어·리소스 포함 여부의 증거이지 물리적 GUI 검증은 아닙니다.

베타 시작 전에 안정판을 종료하고 실제 설정·상태의 `preferences.json`, `lifecycle.json`, `characters/`, 관리 `menu-bar-icons/`를 백업하세요. 설정과 상태를 명시적으로 격리하지 않으면 두 앱은 프로필과 제어 네임스페이스를 공유하므로 동시 실행하지 마세요. 복구할 때는 베타를 종료하고 백업을 복원한 다음 안정판을 시작하세요. 베타가 기록한 데이터의 하위 호환성은 보장되지 않습니다. 삭제 시험에는 **폐기 가능한 연결 워크트리만** 사용하세요. 무시된 파일 삭제·프로세스 종료·패널/작업공간 영향이 가능하므로 중요한 체크아웃을 사용하지 말고 취소 시 요청 0건과 의도적 확인 후 올바른 대상 삭제를 확인하세요. 위 한국어 점검표 링크를 참고하세요.
