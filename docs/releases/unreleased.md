Only explicit `recover --start` may launch a verified candidate or restore a verified original; partial-release reconciliation is idempotent. Unproven manager activity, incomplete evidence and `Unknown` retain the reservation; no reinstall/replay or blind rollback. `Failed` can remain historical and yield a nonzero result after safety/admission has reconciled. A subsequent successful fresh Check requires new user consent rather than replaying the previous failure. User Stop always wins.

- **당시 protocol-2 소스 스냅샷:** 설정 카드의 기본 켜짐·읽기 전용 하루 간격 확인, 지금 확인, 실행 버전·출처, 마지막 성공 확인과 출처별 명시적 적용은 자동 설치/재시작·베타 전환·암묵적 채널 이전·Git pull/reset이 아닙니다. Herdr 원본/ref/호스트, Homebrew 관리자 prefix와 실제 포뮬러 Cellar 루트/채널, 로컬 재빌드와 외부 설치 후보 적용을 구분합니다. 출처 기준 일치나 고정 ref를 전역 최신 릴리스로 부르지 않으며 확인만으로 Brew 캐시를 갱신하지 않습니다.
- 준비 단계는 전체 네이티브 초안·IME·진행 작업·제스처를 보호합니다. 격리된 근거의 독립 도우미 서명은 **로컬 ad-hoc**이지 공식 서명/공증이 아니며 시스템 의존성만 사용하고 설치·프로필 예약과 작업별 lease를 유지합니다. protocol 2 계획/저널에는 `version:2`, 저널에는 `execution_fence:no_spawn|manager_intent|manager_exited`가 필수입니다. 관리자 실행 전에 intent를 기록하며 exited에는 종료·출력 배출 증거가 필요합니다. intent 뒤 PID가 없다고 미실행으로 판정하지 않습니다. protocol 1 계획·저널·표식은 별칭이나 무단 변환 없이 차단·보존합니다. 오프라인 CLI 상태는 현재 프로세스가 아닌 기록이며 서명 검증한 잔여 도우미의 status/recover에서 프로세스·후보를 확인합니다. 살아 있는 작업별 lease는 동시 복구를 거절합니다.
- 정확히 준비된 원본과 NoSpawn의 미실행이 확인되면 원본을 바꾸지 않고 `Failed`, `installed:false`, `applied:false`로 예약을 해제할 수 있으며 종료된 원본은 암묵적 시작 없이 조정합니다. 새로 준비된 **원본**도 종료 여부보다 먼저 확인하며 업그레이드가 아닙니다. 검증된 후보 시작이나 원본 복원은 명시적 `recover --start`에서만 가능하고 부분 표식 해제는 반복 가능하게 조정합니다. 불명확한 관리자/증거 및 `Unknown`은 예약을 유지하며 설치 반복·맹목적 롤백은 없습니다. 안전하게 조정된 `Failed`도 기록으로 남고 종료 코드가 0이 아닐 수 있습니다. 이후 성공적인 새 확인과 새 사용자 동의는 이전 실패의 재실행이 아닙니다. 사용자 Stop이 언제나 우선합니다.
- 실제 충돌 범위는 Herdr checkout 루트(플러그인 하위 디렉터리/소켓/덮어쓴 프로필 아님) 또는 Homebrew의 물리적 포뮬러 Cellar 루트(prefix 전체 아님)입니다. 처음 주입된 호스트 설정, 원본/ref, 선택된 프로필과 외부 에셋을 구분·보존합니다. 동일 설치를 쓰는 다른 실행 중 프로필이 있으면 두 프로필 모두 종료하지 않고 사전 검사를 거절합니다.

## Standalone and remote-only watcher startup fix

### Membership is not health

- A valid local `plugin_list` with no `desktop-pet` row on first observation is **not disable**. Keep local snapshots/subscription available and remote polling alive.
- Explicit `enabled: false` detaches. A missing row **after a previously present enabled or disabled row** detaches as observed unlink. Membership history survives rechecks/reconnects within the daemon, **not a new daemon**.
- When **every registered local endpoint is confirmed disabled/unlinked**, quit immediately, even with a healthy remote or `exit_with_herdr` off. Initially missing is not terminal. Other lost-health cases retain the **30-second grace**; this fix does not convert every missing or unhealthy endpoint into an immediate disable.

### Remote-only operation and diagnosis

- The pet runs on the local Mac. Authenticate a saved machine and **explicitly select its enabled profile** under Observation sources. The remote server needs no `desktop-pet` plugin.
- Optionally set `exit_with_herdr` off via the native CLI **before first start when there is no healthy local server**, and enable it after healthy remote polling. This is an explicit user setting choice, not an automatic policy change.
- Turning local observation off excludes display data, **not lifecycle**. It does not bypass confirmed local disable/unlink termination.
- Diagnose an inherited socket separately from the CLI executable/version. There is **no plugin auto-install, new configuration, or SSH transport change** in this fix. For actual commands and host capability requirements, use the [root guide](../../readme.md) and [integration guide](../../integrations/herdr/README.md).

### 안정판 0.2.0: 연결된 워크트리 삭제

- 로컬 카드 헤더의 우클릭/Control-click은 선택된 카드와 관계없이 클릭한 카드를 대상으로 하고, 대화창 배경은 메뉴를 열 때 선택된 카드를 대상으로 합니다. 메뉴는 대상을 명시하며 적격 대상이 없으면 삭제 항목이 없습니다. 텍스트·컨트롤 네이티브 메뉴는 유지하고 **대화창 닫기**는 여전히 숨기기만 합니다.

### 게시 준비 당시 작업본 추가 기능: 세션 검색·정렬

- 네이티브 말풍선 도구막대의 기본값은 빈 검색어, **전체(All)**, **기본순(Stable)**, **실행 중 우선(Running first) 끔**입니다. 검색어의 앞뒤 공백을 제거하고 대소문자 구분 없이 제목·탭/워크스페이스/에이전트/소스 표시 이름·전체 작업 디렉터리·대체 이름에서 부분 일치시킵니다. ID와 소켓 경로는 검색하지 않습니다. 보유한 모든 관찰 후보에서 상태 필터와 검색을 교집합으로 적용한 뒤, 선택한 기본순/이름순/출처순 정렬 및 128개 제한 **전에** 실행 중 우선을 소스 전체에 적용합니다. 동률은 결정적으로 정렬하며 Recent/Created 정렬은 없습니다. 일치/생략 수는 화면의 카드만이 아닌 제한 전 전체 일치 집합을 기준으로 하고 전체 상태 요약·반응은 바꾸지 않습니다.
- 정확한 세션 키 선택과 세대를 유지합니다. 선택한 답장이 숨겨지면 접되지만 메모리 초안은 남고 검색을 지워도 자동으로 다시 열리지 않습니다. 검색창 Enter/Command-Enter는 답장을 보내지 않으며 Escape는 먼저 IME 조합 취소, 그다음 검색어 삭제, 빈 검색창에서는 말풍선 접기 없이 포커스 종료 순으로 동작합니다. 검색·답장 조합 상태를 각각 추적하여 어느 쪽이든 조합 중이면 구조 변경을 보류하되 실시간 상태는 갱신합니다. 사용자의 옵션 변경은 스크롤을 맨 위로, 배경 갱신은 기존 위치를 유지하거나 범위 내로 제한합니다.
- 정렬·실행 중 우선 설정은 원자적 환경설정 저장 성공 후에만 지속됩니다. 저장에 실패하면 네이티브 오류를 표시하고 컨트롤과 실제 정렬을 되돌립니다. 검색어·상태 필터·선택·초안은 메모리에만 있습니다.
- **정렬 메뉴 통합:** 별도 실행 중 우선 체크박스를 정렬 명령 메뉴의 상호배타 기준 3개·구분선 아래 독립 체크 항목으로 옮겼습니다. 닫힌 제목과 접근성 값은 적용된 두 선택을 함께 표시합니다. 기존 6개 조합·설정 필드·기본값·IME 보류·저장 실패 복원은 그대로입니다. 프로그램 방식 AppKit 메뉴 동작으로 한영 6개 조합, 설정 저장·재읽기, 보류 중 반복 토글·정렬 intent 병합과 거절·저장 실패 복원을 확인했습니다. Window Server가 `CGSSessionScreenIsLocked=1`을 보고하고 네이티브 창 캡처를 생성하지 못했으며, native hosting-view raster로 팝업 글자 가시성은 입증하지 못했습니다. 물리적 마우스·키보드·실제 IME·VoiceOver와 시각적 잘림 검증은 아닙니다.
- **현재 작업본 전용 근거:** production 모델과 프로그램 방식 AppKit smoke에서 후보 127/128/129개, 실행 중 131개 상위 128개, 소스 전체 우선순위, 중복 이름의 검색·필터·정렬·제한, 네이티브 카드 130개, 제한 전 Unicode 검색, 상태 교집합, 숨겨진 정확한 키의 초안 유지·자동 재열기 방지, 실제 설정 저장 및 지역화된 저장 실패 네이티브 창·롤백을 확인했습니다. arm64 release 검사·빌드, 변경 파일 8개 범위 rustfmt, 주 테스트 349개와 제한시간 FIFO child 1개(합계 350개), 기존 입력창 배치 executable이 통과했습니다. 프로그램 방식 관찰은 **물리적 키보드·실제 IME·VoiceOver 검증이 아니며**, 게시 beta나 패키지 검증 근거도 아닙니다.
- **추가 AppKit 근거:** 네이티브 편집기의 marked/unmark/cancel 호출로 확정 한글·이모지와 UTF-16 선택을 유지했고, 조합 중 행을 교체하지 않고 보류된 옵션·실시간 오프라인 상태를 반영했습니다. 세대 교체 후 기존 정확한 키의 초안은 남고 새 세대에는 상속되지 않았습니다. 검색·필터·정렬·실행 중 우선은 사용자 스크롤을 초기화했고, 배경 상태 변경은 위치를 유지했습니다. 같은 세대의 130 → 12 → 130 스냅샷에서는 0이 아닌 문서 최대 위치로 제한한 뒤 복원 시 그 위치를 유지했습니다. 실제 보류 프레임 타이머로 답장 조합 종료 후 캐릭터 숨김/표시를 적용하여 꼬리 없는 단독 말풍선·재부착·초안/옵션 유지, 한영 라이트/다크 raster와 들어갈 수 있는 최소 높이의 답장을 확인했습니다. 네이티브 전송 콜백·production worker는 **연결 전 StaleTarget**을 원래 정확한 키로 반환하며 다른 답장을 보존했고, Unix 연결·`agent.prompt` 전달은 시도하지 않았습니다. 초기 전경 키 검증은 GUI 잠금(`CGSSessionScreenIsLocked=1`, 전경 `loginwindow`)에 막혀 별도 nonkey 성공을 전체 키보드 성공으로 취급하지 않았습니다. **잠금 해제 후 실제 앱의 전체 시나리오가 통과했습니다.** 실제 key-window의 Command-A/C/X/V를 사설 named pasteboard로 처리하여 사용자 클립보드를 건드리지 않았고, 한글·이모지 UTF-16 선택 대체·패널 Escape 라우팅과 나머지 IME·초안·스크롤·단독 말풍선 검사가 통과했습니다. 이는 프로그램 방식 AppKit 입력이지 물리적 키보드·실제 입력기·VoiceOver 인증이 아닙니다.

위 key-window 및 예약 프레임 관찰은 그 뒤의 Search/답장 OR-owner 구조 수정 **이전** 근거입니다. 수정 후의 활성/key Search 조합·선택 affinity·예약 타이머 경로 귀속·네이티브 소유자 겹침 검사는 아닙니다. 수정 전 작업본의 arm64 native 354개, Bun 52개/435 기대값, 할당 피크 469,256바이트, Markdown 소비자 182개 주장도 통합 소스나 새 시험판에서 재검증한 수치가 아닙니다. **이 문서 작성 당시의 화면 꺼진 준비 단계에서는** 실제 GUI 시나리오를 수행하지 못했지만 사용자는 다른 Mac 수동 검증을 위해 병합 및 **새 minor** 격리 `0.3.0-beta.1` 시험판 준비를 허가했습니다. 예정된 `beta/0.3.0-beta.1`에 관한 이 문서 자체는 추후 태그·업로드·실제 GUI 통과의 증거가 아니므로 실제 Release 카탈로그와 바이너리로 확인하세요. 안정판 v0.2.0/latest 및 이전 베타 태그·자산은 이 계획으로 대체하지 않습니다. [실제 베타 수동 점검표](../validation/beta-session-search-validation.ko.md)에 PASS/FAIL/UNEXERCISED와 환경을 기록하세요.

**통합 소스의 게시 전 실행 근거:** `origin/main`의 `21d6eac`과 통합해 네이티브 자동화·rig 말풍선 부착을 유지한 뒤 arm64 release 검사·테스트·빌드와 범위 rustfmt가 통과했습니다. 주 테스트 460개 + 제한시간 FIFO child 1개(보고된 통과 461개), 기존 메인 스레드 composer executable, 매니페스트를 유지한 CLI `0.2.0`, TypeScript 및 Bun 55개/기대값 469개와 안정판 노트 CLI preflight를 확인했습니다. 따옴표가 파일명인 bare 목적지와 다음 줄의 잘못된 괄호 제목 앞에 있는 정상 destination-only 정의가 실제 Release preflight를 빠뜨리는 두 경계를 재현한 뒤 누락 대상을 거부하도록 수정했고 Release·current/frozen Wiki 회귀로 보호합니다. 실제 Search IME·예약 타이머 경로·소유자 겹침 또는 이후 베타 패키지·다운로드를 확인한 근거는 아닙니다.

### 캐릭터·대화창 표시 독립

- 캐릭터를 숨겨도 활성 대화창은 꼬리 없는 이동 가능한 패널로 남고, 캐릭터를 표시하면 다시 붙습니다. 네 가지 표시 조합은 독립적입니다. 독립 대화창 위치는 별도로 저장하고 나중에 다시 분리할 때 복원합니다. 저장된 위치가 없으면 계산만 하고 적용하지 않은 배치가 아닌 **실제로 적용된 부착 본문**을 사용합니다. 우선순위는 저장 위치, 보류 위치, 사용 가능한 부착 배치, 일반 부착 배치 대체 위치 순입니다.
- 실행 중 숨김/표시 전환에도 카드·답장 상태와 초안을 유지합니다. 미확정 문자가 있으면 숨김·표시·배치·초기화 중 단독 위치 저장을 조합 종료까지 보류하며 최신 장면이 우선하고 나중의 초기화는 예전 저장 위치를 지운 뒤 새로 적용된 부착 본문에서 다시 설정합니다. 실제 입력창 콜백에서 조합 문자·확정 초안·선택 위치가 유지되고 조합 중 부착 창·입력창 프레임은 변하지 않았지만 키보드 포커스·물리적 IME는 검증되지 않았습니다. **초안은 재시작 후 복원하지 않습니다.** 숨김은 앱이나 Herdr 세션 종료가 아닙니다.
- 전체 클릭 통과는 **두 창 모두**, 알파 클릭 통과는 **캐릭터 그림에만** 적용합니다. 독립 상태의 대화창 배치 설정 변경은 다시 붙을 때까지 기다립니다. 위치 초기화는 두 위치만 초기화하며 표시 여부는 바꾸지 않습니다. 대화창 닫기는 여전히 대화창만 숨깁니다.

### 안정판 0.2.0: 답장 복사·붙여넣기 단축키 (beta3 포함, beta2 미포함)

- 답장창에는 네이티브 `paste:`가 있었지만 Edit 메뉴가 없는 패널의 Command 단축키 연결이 없었습니다. 기존 대사 편집창과 같은 방식으로 포커스가 있는 `performKeyEquivalent:`와 `keyDown:` 대체 경로에서 Command-A/C/X/V를 네이티브 전체 선택·복사·잘라내기·붙여넣기로 보냅니다. 기존 한 줄 정규화·UTF-16 선택·IME 소유권을 유지하고 추가 Shift/Option/Control이나 조합 중 입력을 가로채지 않습니다.
- **beta3 AppKit 확인:** 일회성 메인 스레드 프로세스에서 production `ComposerView`·`BubblePanel`, 네이티브 키 이벤트와 사설 named pasteboard로 한글·이모지·CRLF 붙여넣기, UTF-16 선택 대체, 전체 선택·복사·잘라내기, Caps Lock·포커스·추가 modifier·조합 보호를 확인했습니다. 실제 사용자 클립보드는 읽거나 쓰지 않았습니다. 프로브 파일·후크를 제거하고 정확한 production 소스를 복구한 다음 새 격리 beta3 TypeScript·Bun 44개(기대값 355개)·범위 rustfmt·네이티브 arm64 release 검사·빌드·테스트 343개(주 342개 + FIFO child 1개), 기존 AppKit 배치 executable도 통과했습니다. 클립보드 근거는 일회성 프로그램 AppKit 입력이며 영구 테스트 추가나 물리적 키보드·실제 IME 인증이 아닙니다.
- **게시 채널 경계:** 게시된 beta2의 `beta/0.2.0-beta.2` 태그·자산에는 이 후속 수정이 없고 교체하지 않았습니다. **beta3 게시 당시** 갱신형 베타 포뮬러는 tap `2d6ec6a9ae3427367883a45e469cf3e82fe8f8dd`의 `0.2.0-beta.3`을 가리켰습니다. beta3 압축파일의 별도 SHA-256은 `14bf452aa492fa520a4979ca3e18711e505c52c178c1e1e2edb355b2b07b0920`이며 인증 없는 다운로드·서명/자원 확인·beta2 → beta3 업그레이드·신규 설치는 위에 기록한 독립 증거로, 이전 beta2 검사나 클립보드 smoke에서 추론한 것이 아닙니다. **현재 안정판 소스 매니페스트는 0.2.0**이며 beta3 자산·검사는 안정판 출시 증거가 아닙니다.

### 독립 실행·원격 전용 관찰 시작 수정

- 최초 로컬 `plugin_list`에 `desktop-pet` 행이 없어도 정상 목록이라면 비활성화가 아닙니다. 로컬 스냅샷·구독과 원격 폴링을 유지합니다. 명시적 `enabled: false`는 분리하며, 이전에 활성/비활성 행이 있었는데 이후 사라지면 관찰된 연결 해제로 분리합니다. 이 이력은 같은 데몬의 재확인·재연결 동안 유지하지만 새 데몬에는 이어지지 않습니다.
- **등록된 모든 로컬 엔드포인트가 비활성화/연결 해제로 확인되면 즉시 종료**합니다. 정상 원격이 있거나 `exit_with_herdr`가 꺼져 있어도 같습니다. 처음부터 행이 없는 것은 종료 조건이 아니며 다른 정상 연결 상실은 기존 **30초 유예**를 유지합니다.
- 원격 전용이어도 펫은 로컬 Mac에서 실행합니다. 저장된 머신을 인증한 뒤 관찰 소스에서 **활성 프로필을 직접 선택**하세요. 원격 서버에는 `desktop-pet` 플러그인이 필요 없습니다. 정상 로컬 서버 없이 처음 시작하려면 선택적으로 네이티브 CLI에서 `exit_with_herdr`를 미리 끄고, 정상 원격 폴링을 확인한 뒤 켤 수 있습니다. 자동 정책 변경이 아닙니다.
- 로컬 관찰을 끄는 것은 표시 데이터만 제외하며 **수명주기 정책은 끄지 않습니다**. 상속된 소켓 문제와 CLI 실행 파일/버전 문제를 따로 진단합니다. 플러그인 자동 설치, 새 설정, SSH 전송 변경은 없습니다. 원격 카드는 여전히 읽기 전용이고, 로컬 프롬프트 접수 확인은 작업 완료가 아닙니다.
- 원래 회귀 기록은 플러그인 응답을 지연하지 않고 pending-source 상태를 수집하며, 비활성화 판단 뒤 **새 소스**로 워커 생존을 입증합니다. 멤버십 이력과 실제 Enabled 복원도 확인해야 합니다. 과거 네이티브 프로브·테스트 수는 당시 보고된 근거일 뿐 이 문서 작업의 새 검증, 실제 키보드 IME·OS 포커스 보장, 공개 배포 증거가 아닙니다.

### 안정판 0.2.0의 저장소 버전 문서와 발행 자동화

원래 문서·게시 도구 변경은 과거 `9cbad32` 시기의 로컬 미병합 네이티브 네 묶음과 별도로 `main`에 반영됐습니다. 그 제한은 현재의 안정판 0.2.0 승격을 막지 않습니다. 검토한 버전별 기록·마이그레이션 문서는 저장소가 원본이며 Wiki는 생성된 읽기 화면입니다. 안정판 릴리스는 태그·앱 버전 매니페스트·검토한 해당 버전 문서를 빌드 전에 확인하고 같은 태그 문서로 GitHub Release 본문을 생성합니다. Wiki는 기본 브랜치의 고정된 커밋과 실제 Release·업로드 완료 자산으로 생성하며 수동 작성 페이지를 유지합니다. Markdown URL은 기존 `%29`·`%2529` 및 쿼리·조각을 보존하면서 리터럴 괄호만 인코딩하고, 링크/이미지가 공유하는 참조에서는 이미지 대상만 바꿉니다. 이전 임시 Git 현재·동결 태그(HEAD에서 삭제된 자산 포함)의 **오프라인** Release/Wiki CLI 실험에서 반복 출력 바이트·수정 시각이 같았고 잘못된 경로 사전 검사는 출력을 유지했습니다. 당시 대상 consumer 테스트는 32개·241 expects였습니다. 이는 네트워크 Wiki 게시나 현재 안정판 0.2.0 패키지 검증 결과가 아닙니다. Wiki 발행 실패는 이미 성공한 바이너리 Release를 취소하지 않습니다. [운영·복구 절차](publishing.md)를 따르세요.

**현재 소스 인라인 마스킹 수정(선택한 beta2 스냅샷에 포함):** 외부 후보를 마스킹·변환하기 전에 완전한 인라인 구문과 실제 내부 bracket 링크의 우선순위를 판정합니다. 잘못된 괄호 제목이나 실제 inline/정의된 reference 링크 때문에 무효인 외부 링크는 내부 링크·이미지를 변환·preflight 대상으로 남깁니다. 미정의 괄호 텍스트만으로 정상 외부 링크를 무효화하지 않으며 URL·제목의 이미지 모양 문자, 기존 angle destination의 공백 없는 제목, 이미지-in-link mixed reference 동작은 유지합니다. 앞선 오프라인 Release·current/frozen Wiki CLI에서 Guide의 태그·매핑 링크와 Art의 raw 이미지 URL을 확인하고 누락·저장소 밖 내부 대상을 거부했으며 이전 출력 바이트·mtime·Wiki manifest를 보존했습니다. HEAD에서 삭제한 자산은 태그에서 계속 읽고 HEAD에만 있는 파일은 누락된 태그 객체를 복구하지 못했습니다. 대상 consumer 테스트는 34개·295 expects, TypeScript와 전체 프로젝트 테스트는 44개·355 expects로 통과했습니다. 이는 이전 소스 검사이지 새로운 beta2 게시·패키지 검증 근거가 아닙니다.
