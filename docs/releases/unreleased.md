## Current working-copy additions: menu-bar visibility and image

- The default status icon is a template pawprint; a chosen image changes its artwork, not its status item or menu. A native **Menu bar icon / 메뉴 막대 아이콘** setting in the existing three-tab Settings panel offers **Always show / 항상 표시** (`always`) and **Only when recovery is needed / 복구가 필요할 때만 표시** (`recovery_only`). Missing `menu_bar_mode` in `preferences.json` defaults to Always, including existing profiles from the original checkout; no profile recreation is needed. An explicit RecoveryOnly choice persists across restart and unrelated preference saves.
- Always displays the icon while the app runs. RecoveryOnly displays it only when both character and bubble are hidden **or** full-window passthrough is on; interactive standalone bubble alone is not a trigger, nor is alpha pointer passthrough alone. Both modes offer **Settings… / 설정…** and **Quit / 종료**; **Show and Enable Character / 캐릭터 표시·조작 복구** appears only while recovery is needed. Recovery shows the character and clears full-window passthrough, preserving bubble visibility and alpha passthrough. With Always the icon stays; with RecoveryOnly it disappears after the recovery menu closes when no longer needed.
- A successful selection changes only the menu-bar mode; it does not change character/bubble visibility, full-window or alpha passthrough, placement, drafts, or lifecycle. A failed save leaves the prior selected mode and live icon behavior in place. Existing unknown/unrelated preferences are preserved. This is not a new CLI mode command, hotkey, badge, onboarding flow, version, or release.
- **Choose image… / 이미지 선택…** imports a static PNG of up to 4 MiB encoded and 1 million decoded pixels; animation, corruption, truncation, and fully transparent images are rejected. The image retains original colors and aspect-fits within 18 pt with 1×/2× Retina representations. **Restore default icon / 기본 아이콘 복원** returns to the template pawprint. An optional `preferences.json` `menu_bar_icon.asset` references a managed copy under the configuration directory's `menu-bar-icons/`; external originals can be moved or deleted. Back up `menu-bar-icons/` with `preferences.json`, `lifecycle.json`, and `characters/`. Without an icon preference, the default pawprint remains. Import/save failure retains the prior image and settings; a missing/corrupt managed image at restart displays the default with an error but keeps custom metadata. Reset affects only the image, not visibility mode or other settings.
- Source images are opened nonblocking and checked as regular files on the same opened descriptor before any read. This rejects a FIFO with no writer without waiting and still permits symlinks to regular PNGs; the existing byte/pixel limits and managed-asset rules remain unchanged. This is not a universal latency guarantee for network filesystems.
- PNG import verifies every chunk CRC (including ancillary chunks and IEND), IDAT zlib Adler-32, and the exact inflated scanline bound for the color format and interlace passes before native decoding; the existing 4 MiB/1-million-pixel limits and supported formats remain unchanged. Managed publication is atomic and does not replace an existing file. An older interrupted import's confirmed owned/private same-inode temporary alias can be repaired by explicitly reimporting the identical valid PNG; startup does not sweep aliases, and arbitrary hardlinks or corrupt files are not repaired.
- Earlier native unit/transaction gates and an isolated native startup recorded source removal/restart, checksum rejection, and syscall-interposed crashes before/after exclusive rename with same-PNG retries; this is historical evidence, not a chooser check in the current run. In a separate current-binary startup check, an **already-installed private managed PNG** was seeded, its external source deleted, and the actual app restarted. The real `herdr-pet-menu` status-button image remained non-template at 18 pt with 18×18 and 36×36 bitmap representations; the saved choice and unknown preferences survived. This establishes managed-asset startup restoration, **not** chooser/import behavior. Settings was opened via the real status-menu action, but a top-layer Window Server shield prevented actual chooser Cancel/valid/corrupt PNG clicks, visual/icon interaction, and VoiceOver checks. The shield does not establish whether the screen was locked. This is not release or full visual proof.
- In that same actual Settings panel, AppKit `performClick` on the enabled **Restore default icon** button ran the production reset callback. The real status image became a template, `preferences.json` lost **only** `menu_bar_icon` with every other known/unknown field unchanged, and the old owned managed PNG was unlinked. This guarded button callback is not physical-click, chooser, or VoiceOver proof.

## Standalone and remote-only watcher startup fix

### Membership is not health

- A valid local `plugin_list` with no `desktop-pet` row on first observation is **not disable**. Keep local snapshots/subscription available and remote polling alive.
- Explicit `enabled: false` detaches. A missing row **after a previously present enabled or disabled row** detaches as observed unlink. Membership history survives rechecks/reconnects within the daemon, **not a new daemon**.
- When **every registered local endpoint is confirmed disabled/unlinked**, quit immediately, even with a healthy remote or `exit_with_herdr` off. Initially missing is not terminal. Other lost-health cases retain the **30-second grace**; this fix does not convert every missing or unhealthy endpoint into an immediate disable.

### Remote-only operation and diagnosis

- The pet runs on the local Mac. Authenticate a saved machine and **explicitly select its enabled profile** under Observation sources. The remote server needs no `desktop-pet` plugin.
- Optionally set `exit_with_herdr` off via the native CLI **before first start when there is no healthy local server**, and enable it after healthy remote polling. This is an explicit user setting choice, not an automatic policy change.
- Turning local observation off excludes display data, **not lifecycle**. It does not bypass confirmed local disable/unlink termination.
- Diagnose an inherited socket separately from the CLI executable/version. There is **no plugin auto-install, new configuration, or SSH transport change** in this fix. For actual commands and host capability requirements, use the [root guide](../../readme.md) and [integration guide](../../integrations/herdr/README.md).

### Regression evidence and method

The original local pending-checkout record describes watcher transport regressions that capture pending-source state **without delaying plugin responses**. A **fresh source** proves worker survival after the disable decision; checking only a retained snapshot would not prove that. Membership history and actual **Enabled restoration** remain checked, so survival alone is not enough to establish correct lifecycle behavior. This is reported evidence for the local implementation, not new verification in this documentation change or evidence of a `main` merge.

Historical native reply probes and test counts belong in the [v0.1.6 evidence appendix](v0.1.6.md#historical-evidence-appendix). They do not establish that these Unreleased source changes have been published.

### 현재 작업본 추가 기능: 메뉴 막대 표시 조건·이미지 선택

- 기존 `bf23ced` 기록의 위 조건부 복구 정책은 역사적 근거이며, 지금 작업본의 기본 동작이 아닙니다. 기본 상태 아이콘은 템플릿 발바닥 그림이며 사용자 지정 이미지는 같은 상태 아이템·메뉴의 그림만 바꿉니다. 기존 3탭 설정 패널의 **메뉴 막대 아이콘 / Menu bar icon**에서 **항상 표시 / Always show** (`always`) 또는 **복구가 필요할 때만 표시 / Only when recovery is needed** (`recovery_only`)를 선택합니다. 기존 프로필에서 `preferences.json`의 `menu_bar_mode`가 없어도 항상 표시가 기본이며 프로필 재생성은 필요 없습니다. 명시적으로 선택한 복구 시에만 표시는 재시작과 다른 설정 저장 후에도 유지됩니다.

- 선택 저장이 성공하면 메뉴 막대 모드만 바꾸며 창 표시·전체/투명 영역 클릭 통과·위치·초안·실행 관리는 바꾸지 않습니다. 저장 실패 시 이전 선택과 아이콘 동작을 유지하고 모르는 키·무관한 설정도 보존합니다. 이는 새 CLI 모드 명령·단축키·배지·첫 실행 안내·버전·릴리스가 아닙니다.

- 원본 이미지는 nonblocking으로 열고 **같은 열린 descriptor**에서 일반 파일인지 확인한 뒤 읽습니다. writer 없는 FIFO를 기다리지 않고 거부하며 일반 PNG를 가리키는 symlink는 허용합니다. 기존 바이트·픽셀 제한과 관리 사본 규칙은 유지합니다. 모든 네트워크 파일시스템의 지연을 보장하는 변경은 아닙니다.
- PNG 가져오기는 네이티브 디코딩 전에 모든 청크의 CRC(부가 청크와 IEND 포함), IDAT zlib Adler-32, 색 형식·인터레이스 패스에 따른 압축 해제 스캔라인의 정확한 크기 상한을 확인합니다. 기존 인코딩 4 MiB·100만 픽셀 제한과 지원 형식은 그대로입니다. 관리 파일은 기존 파일을 교체하지 않고 원자적으로 게시합니다. 예전 작업본에서 중단된 가져오기로 남은 **소유가 확인된 비공개 동일 inode 임시 하드링크**에 한해서 동일한 유효 PNG를 **이미지 선택…**으로 명시적으로 다시 가져오면 복구할 수 있습니다. 시작 시 임시 파일을 일괄 정리하지 않으며 임의의 하드링크·손상 파일은 복구하지 않습니다.
- 이전 네이티브 단위·트랜잭션 게이트와 격리된 네이티브 시작에서 원본 삭제 후 재시작, 체크섬 거부, 배타적 rename 전후의 syscall 삽입 강제 종료와 동일 PNG 재시도를 기록했습니다. 이는 과거 증거이며 현재 실행에서 이미지 선택 창을 확인했다는 뜻이 아닙니다. 별도의 현재 바이너리 시작 확인에서는 **이미 설치된 비공개 관리 PNG**를 환경설정에 지정하고 외부 원본을 삭제한 뒤 실제 앱을 재시작했습니다. 실제 `herdr-pet-menu` 상태 버튼 이미지는 비템플릿·18 pt에 18×18·36×36 비트맵 표현을 유지했고 선택과 알 수 없는 설정도 보존됐습니다. 관리 자산의 시작 시 복원 증거이지 이미지 선택 창·새 가져오기 증거는 아닙니다. 실제 상태 메뉴 동작으로 설정 창에 도달했지만 Window Server 최상위 가림 창 때문에 이미지 선택 취소·정상/손상 PNG 클릭, 시각적 아이콘 상호작용, VoiceOver는 확인하지 못했습니다. 가림 창만으로 화면 잠김 여부를 단정할 수 없으며 릴리스나 전체 시각 검증 증거도 아닙니다.

### 현재 작업본 추가 기능: 연결된 워크트리 삭제

- 로컬 카드 헤더의 우클릭/Control-click은 선택된 카드와 관계없이 클릭한 카드를 대상으로 하고, 대화창 배경은 메뉴를 열 때 선택된 카드를 대상으로 합니다. 메뉴는 대상을 명시하며 적격 대상이 없으면 삭제 항목이 없습니다. 텍스트·컨트롤 네이티브 메뉴는 유지하고 **대화창 닫기**는 여전히 숨기기만 합니다.
- **워크트리 삭제… / Remove Worktree…**는 현재 로컬의 실행 중인 유효한 세대에서 중복 없이 일치하는 연결 워크트리 메타데이터가 있어야 합니다. 메인 저장소 루트는 제외합니다. 선택적 메타데이터가 없거나 잘못되면 관찰은 유지하지만 삭제 항목은 표시하지 않습니다. 메타데이터가 있으나 서버가 `worktree.remove`를 지원하지 않으면 실행 시 우회 없이 미지원 한계를 알리며, 미지원만으로 항목이 반드시 숨겨지는 것은 아닙니다. 확인 창은 **취소**가 첫 번째·기본 선택(Return·숫자 키패드 Enter·Escape), **삭제**가 두 번째이며 저장소·정확한 체크아웃·워크스페이스·탭/패널/프로세스·브랜치 유지와 **무시된 파일도 삭제됩니다**를 표시합니다. `force: false`여도 무시된 파일은 삭제될 수 있습니다.
- 대상은 고정한 뒤 확인 후 새 스냅샷에서 재검증합니다. 한 번에 하나만 실행하며 IME 조합 중 삭제를 비활성화하고 실행 시 다시 확인합니다. 전용 비동기 `worktree.remove` 요청 하나에 `{workspace_id, force: false}`를 보내며 git/셸 우회·강제 삭제·자동 신뢰·재시도·낙관적 제거가 없습니다. 행 삭제·선택 변경·창 숨김 후 재표시에도 공통 대화창 피드백을 유지합니다. 쓰기 시도 후 전달 여부가 불분명하면 명시하고 자동 재전송하지 않습니다. 일반 watcher의 약 5초 갱신이 최종 관찰 기준입니다.
- 리뷰 수정: 네이티브 확인 창의 배치 뒤 취소 `NSButtonCell`을 창 기본 버튼으로 명시하며, 안전하게 설정할 수 없으면 삭제를 중단합니다. 범위가 확인 창에 한정된 Escape 모니터가 alert cell 재차용 없이 실제 취소 동작을 실행하고 결과 처리 전에 제거됩니다. 작은 보기에서는 긴 대상명보다 지역화된 결과를 먼저 표시하고 전달 불명 시 재시도 전 확인을 안내합니다. 펼친 본문·작은 보기 tooltip·접근성에는 전체 체크아웃과 서버·offline 상세를 유지합니다. 피드백이 있을 때만 줄 수 제한을 풀고 실제 높이를 먼저 확보하여 최소 120 pt 본문과 상태 ON/OFF에서도 주 대화보다 결과를 우선합니다. 일반 작은 보기 대화의 두 줄 정책은 유지합니다.
- **이전 워크트리 삭제 근거:** 네이티브 release 검사·테스트·빌드가 통과했습니다(주 테스트 332개와 제한시간이 있는 FIFO child). 동작 테스트는 오래된/교체된 대상·세대·중복·엄격한 응답·거부·전달 불명/재전송 방지·잠금 없는 전송·작은 보기 결과 우선 배치·일반 파일/FIFO 입력 경계를 다룹니다. 새 AppKit 데몬의 격리 실행에서 UI/control/registration/data 준비를 확인했고, 실제 production sender와 순정 Herdr 0.9.3의 일회용 Git 워크트리 실험에서는 깨끗한 연결 체크아웃·워크스페이스·패널·실행 프로세스가 제거되고 브랜치·무관한 메인 체크아웃은 유지되었습니다. 변경된 tracked/untracked/submodule 및 잠긴 워크트리는 거부되어 데이터가 유지됐고 메인 루트는 클라이언트·백엔드에서 거부됐습니다. 수정 smoke에서는 writer 없는 FIFO의 즉시 거부·일반 PNG/symlink 색 보존을 확인했고, 실제 네이티브 offscreen 필드의 96 pt 폭에서 한·영 전달 불명 안내가 잘리지 않으며 전체 대상 상세와 상태 ON/OFF 결과 공간이 유지됨을 확인했습니다.
- **현재 수정 근거(이전 수치와 별개):** 네이티브 arm64 release 검사·테스트·빌드가 통과했습니다(주 테스트 342개와 격리 FIFO child 1개, 합계 343개). UI 범위 rustfmt는 통과했지만 전체 작업공간 rustfmt는 건드리지 않은 기존 파일 4개에서 실패합니다. 현재 실제 격리 AppKit 바이너리와 자체 Herdr 백엔드에서 상태 메뉴의 실제 동작으로 설정을 열고, 말풍선 펼치기와 실제 카드 접근성 누르기로 실제 입력창을 열었습니다. 디버거를 통해 메인 실행 루프에서 공개 AppKit `setMarkedText`/`unmarkText` 콜백을 호출한 결과 숨김·표시·초기화·배치를 거쳐 조합 문자·확정 초안·선택 위치가 유지되고 조합 중 부착 창·입력창 프레임은 변하지 않았습니다. 모르는 환경 설정 필드는 설정 조작·위치 저장 뒤에도 유지됐습니다. 실제 물리적 IME나 활성 포커스의 증거는 아닙니다. Window Server 최상위 가림 창으로 앱 창 클릭·입력이 막혀 실제 우클릭, 확인 창 Return·숫자 키패드 Enter·Escape(탭으로 삭제에 포커스를 둔 경우 포함), tooltip hover, 이미지 선택 취소·정상/손상 PNG, 포인터 제스처, VoiceOver는 확인하지 못했습니다. 명시적 취소 기본 cell 설정과 offscreen 렌더링을 키 입력·화면 조작의 증거로 보거나 가림 창만으로 화면 잠김 여부를 단정하지 마세요.
- API는 `workspace_id`만 받고 예상 체크아웃/세대의 원자적 대조(CAS)가 없습니다. 클라이언트 재검증 뒤 재시작·워크스페이스 재연결 경합까지 원자적으로 막는다고 보장하지 않습니다. 되돌리기·휴지통·브랜치 삭제는 없으며 이 API의 호환성은 별도 패치가 필요한 client-attach 자동 시작과 독립적입니다. 순정 0.9.3 실험을 0.9.0 지원 증거로 해석하지 마세요.

### 캐릭터·대화창 표시 독립

- 캐릭터를 숨겨도 활성 대화창은 꼬리 없는 이동 가능한 패널로 남고, 캐릭터를 표시하면 다시 붙습니다. 네 가지 표시 조합은 독립적입니다. 독립 대화창 위치는 별도로 저장하고 나중에 다시 분리할 때 복원합니다. 저장된 위치가 없으면 계산만 하고 적용하지 않은 배치가 아닌 **실제로 적용된 부착 본문**을 사용합니다. 우선순위는 저장 위치, 보류 위치, 사용 가능한 부착 배치, 일반 부착 배치 대체 위치 순입니다.
- 실행 중 숨김/표시 전환에도 카드·답장 상태와 초안을 유지합니다. 미확정 문자가 있으면 숨김·표시·배치·초기화 중 단독 위치 저장을 조합 종료까지 보류하며 최신 장면이 우선하고 나중의 초기화는 예전 저장 위치를 지운 뒤 새로 적용된 부착 본문에서 다시 설정합니다. 실제 입력창 콜백에서 조합 문자·확정 초안·선택 위치가 유지되고 조합 중 부착 창·입력창 프레임은 변하지 않았지만 키보드 포커스·물리적 IME는 검증되지 않았습니다. **초안은 재시작 후 복원하지 않습니다.** 숨김은 앱이나 Herdr 세션 종료가 아닙니다.
- 전체 클릭 통과는 **두 창 모두**, 알파 클릭 통과는 **캐릭터 그림에만** 적용합니다. 독립 상태의 대화창 배치 설정 변경은 다시 붙을 때까지 기다립니다. 위치 초기화는 두 위치만 초기화하며 표시 여부는 바꾸지 않습니다. 대화창 닫기는 여전히 대화창만 숨깁니다.

### 현재 작업본 수정: 답장 입력 글자 잘림

- 기존 22 pt 외부 입력창 대신 네이티브 텍스트 한 줄과 테두리·스크롤러 공간을 함께 확보하고 답장 행·카드·말풍선까지 측정 높이를 전달합니다. 긴 글 → 짧은 글/빈 글의 문서 폭과 가로 이동 범위를 초안·선택을 다시 쓰지 않고 맞춥니다. 조합 중 앱 배치는 보류하며, 짧은 화면에서는 들어갈 수 있는 선택 답장·메시지 한 줄을 여백 축소로 먼저 확보합니다.
- **실제 production 근거:** 자체 Herdr 0.9.3 백엔드·대기 중인 OMP 세션에 연결한 서명된 격리 앱에서 보고된 초안의 Legacy 외부/clip/문서 높이는 **22/3/5 → 43/24/24 pt**로 바뀌었고 16 pt 텍스트 줄과 상위 뷰 clipping 범위를 확보했습니다. 네이티브 창 raster에서 글자가 보입니다. production 숨김·표시·초기화·배치 콜백 후 동일 입력창·초안·UTF-16 선택 범위·affinity를 유지하고 네이티브 입력으로 선택 영역을 대체했습니다. marked/unmark 콜백에서 조합·편집 상태와 조합 중 프레임을 유지했으며 실제 Overlay에서도 글자 공간을 확보했습니다. 원상 복구한 **프로세스 내부 가상 260 pt 화면 높이 fixture**에서도 선택 답장·주 메시지가 보였으나 물리적 모니터 검증은 아닙니다.
- **이전 소스 회귀·게이트이며 beta2 새 배포 검증이 아님:** arm64 release 검사·테스트·빌드가 통과했습니다(주 테스트 342개 + 제한시간이 있는 FIFO child 1개 = 343개, **별도로 실제 메인 스레드 AppKit 입력창 executable 통과**). production 배치 모듈로 두 실제 스타일, 95/220/390 pt 폭, 빈/짧은/긴 한글·영문·이모지, 폭 축소·가로 범위·네이티브 이동·재부착·선택 대체·조합 상태를 확인합니다. 변경 파일 범위 rustfmt와 앞선 입력창 게이트의 TypeScript·프로젝트 테스트 42개(301 expects)가 통과했고, 이후 합쳐진 현재 소스 게이트는 Bun 44개(355 expects)입니다. 콜백·raster는 실제 키보드 포커스·IME·포인터 검증을 대신하지 않습니다.
- **beta2 변경:** 동결된 `beta/0.2.0-beta.1` 자산과 **당시의 beta1 포뮬러 리비전**에는 보고된 문제가 남아 있습니다. 현재 갱신형 베타 포뮬러는 beta2로 옮기며 beta1에 고정해 두지 않습니다. 선택한 beta2 스냅샷에는 수정이 포함되지만 공개 `main` 병합·원본 0.1.11 매니페스트 변경·안정판 교체·프로필 이전은 하지 않습니다. GUI 수동 점검은 [마이그레이션 안내](../migrations/unreleased.ko.md#현재-작업본-수정-답장-입력-글자-잘림)를 따르세요.

### 독립 실행·원격 전용 관찰 시작 수정

- 최초 로컬 `plugin_list`에 `desktop-pet` 행이 없어도 정상 목록이라면 비활성화가 아닙니다. 로컬 스냅샷·구독과 원격 폴링을 유지합니다. 명시적 `enabled: false`는 분리하며, 이전에 활성/비활성 행이 있었는데 이후 사라지면 관찰된 연결 해제로 분리합니다. 이 이력은 같은 데몬의 재확인·재연결 동안 유지하지만 새 데몬에는 이어지지 않습니다.
- **등록된 모든 로컬 엔드포인트가 비활성화/연결 해제로 확인되면 즉시 종료**합니다. 정상 원격이 있거나 `exit_with_herdr`가 꺼져 있어도 같습니다. 처음부터 행이 없는 것은 종료 조건이 아니며 다른 정상 연결 상실은 기존 **30초 유예**를 유지합니다.
- 원격 전용이어도 펫은 로컬 Mac에서 실행합니다. 저장된 머신을 인증한 뒤 관찰 소스에서 **활성 프로필을 직접 선택**하세요. 원격 서버에는 `desktop-pet` 플러그인이 필요 없습니다. 정상 로컬 서버 없이 처음 시작하려면 선택적으로 네이티브 CLI에서 `exit_with_herdr`를 미리 끄고, 정상 원격 폴링을 확인한 뒤 켤 수 있습니다. 자동 정책 변경이 아닙니다.
- 로컬 관찰을 끄는 것은 표시 데이터만 제외하며 **수명주기 정책은 끄지 않습니다**. 상속된 소켓 문제와 CLI 실행 파일/버전 문제를 따로 진단합니다. 플러그인 자동 설치, 새 설정, SSH 전송 변경은 없습니다. 원격 카드는 여전히 읽기 전용이고, 로컬 프롬프트 접수 확인은 작업 완료가 아닙니다.
- 원래 회귀 기록은 플러그인 응답을 지연하지 않고 pending-source 상태를 수집하며, 비활성화 판단 뒤 **새 소스**로 워커 생존을 입증합니다. 멤버십 이력과 실제 Enabled 복원도 확인해야 합니다. 과거 네이티브 프로브·테스트 수는 당시 보고된 근거일 뿐 이 문서 작업의 새 검증, 실제 키보드 IME·OS 포커스 보장, 공개 배포 증거가 아닙니다.

### main의 저장소 버전 문서와 발행 자동화

문서·게시 도구 변경은 위의 로컬 미병합 네이티브 네 묶음과 별개로 `main`에 반영됩니다. 검토한 버전별 기록·마이그레이션 문서는 저장소가 원본이며 Wiki는 생성된 읽기 화면입니다. 앞으로 릴리스는 태그·앱 버전 매니페스트·검토한 해당 버전 문서를 빌드 전에 확인하고 같은 태그 문서로 GitHub Release 본문을 생성합니다. Wiki는 기본 브랜치의 고정된 커밋과 실제 Release·업로드 완료 자산으로 생성하며 수동 작성 페이지를 유지합니다. Markdown URL은 기존 `%29`·`%2529` 및 쿼리·조각을 보존하면서 리터럴 괄호만 인코딩하고, 링크/이미지가 공유하는 참조(중첩·여러 줄 또는 들여쓰기 없는 다음 줄 제목 포함)에서는 이미지 대상만 바꿉니다. 외부 URL·제목 속 `![Art]`는 건드리지 않습니다. 이전의 실제 임시 Git 현재·동결 태그(HEAD에서 삭제된 자산 포함)와 raw/blob·매핑/tree 경로를 사용한 **오프라인** production Release/Wiki CLI 실험에서 반복 실행 후 바이트·수정 시각이 같았고 잘못된 경로 사전 검사는 출력을 유지했습니다. 당시 대상 consumer 테스트는 32개 통과·241 expects이며 잘못된 참조 정의 제목·라벨은 일반 문장으로 남기고 정상 인라인 링크의 대상·제목은 이미지 스캔에서 제외하는 사례도 다룹니다. 네트워크 게시를 실행한 것은 아닙니다. Wiki 발행 실패는 이미 성공한 바이너리 Release를 취소하지 않습니다. [운영·복구 절차](publishing.md)를 따르세요. 이 문서·자동화 변경은 네이티브 기능 병합, 새 바이너리 발행이나 다음 버전 지정, 기존 v0.1.11 배포 파일 변경이 아닙니다.

**현재 소스 인라인 마스킹 수정(선택한 beta2 스냅샷에 포함):** 외부 후보를 마스킹·변환하기 전에 완전한 인라인 구문과 실제 내부 bracket 링크의 우선순위를 판정합니다. 잘못된 괄호 제목이나 실제 inline/정의된 reference 링크 때문에 무효인 외부 링크는 내부 링크·이미지를 변환·preflight 대상으로 남깁니다. 미정의 괄호 텍스트만으로 정상 외부 링크를 무효화하지 않으며 URL·제목의 이미지 모양 문자, 기존 angle destination의 공백 없는 제목, 이미지-in-link mixed reference 동작은 유지합니다. 앞선 오프라인 Release·current/frozen Wiki CLI에서 Guide의 태그·매핑 링크와 Art의 raw 이미지 URL을 확인하고 누락·저장소 밖 내부 대상을 거부했으며 이전 출력 바이트·mtime·Wiki manifest를 보존했습니다.
