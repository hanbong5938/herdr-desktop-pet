# Herdr Desktop Pet v0.3.1 release notes

[Versions](README.md) · [0.3 release line and bilingual upgrade](0.3.md) · [CLI contract](../cli.md)

## English

v0.3.1 is the stable source/default-prebuilt target for the integrated 0.3 line. Actual publication requires the non-draft, non-prerelease GitHub Release and complete arm64 archive, archive checksum and `SHA256SUMS`; a source version or tag alone is not a published binary.

### Included capabilities

- Session search, intersecting status filtering, Stable/Name/Source ordering and independent Running first, without changing observed session status.
- Native automation CLI for presentation, preferences, sessions, dialogue, characters and updater status/recovery. Operation identity and terminal state remain authoritative; prompt acceptance is not agent completion.
- Conflict-aware saved-dialogue drafts with explicit Reload saved and Rebase draft, preserving active composition and blocking stale saves.
- Eight-way bubble edge/corner resizing, contextual Settings and independent character/bubble visibility.
- Native installed/official character browser with explicit verified Download & Apply. Imported Arin compatibility from v0.2.1 is retained.
- Installation-aware protocol-2 updates: read-only automatic/manual checks, explicit native consent, guarded rebuild/upgrade/apply and standalone durable recovery. No silent install, beta switch, Git pull/reset or uncertain manager replay.
- Rig-worker JIT decoding support, with `allow-jit` confined to the worker, not the app or updater helper.

The [v0.3.0 frozen source note](v0.3.0.md) records the detailed inherited implementation and scoped evidence. Existing tags/beta assets, character-pack v5, bundled `default@0`, artwork and licensing remain unchanged.

### Publication repair

The [v0.3.0 Release workflow](https://github.com/hanbong5938/herdr-desktop-pet/actions/runs/37824652666) failed twice before publishing assets: the dialogue-list deadline fixture required its first status poll inside a 180ms window. v0.3.0 remains a tag-only source snapshot, not a published binary release.

v0.3.1 repairs only that test's scheduling assumptions: immediate Pending acknowledgement, a two-second poll window and a terminal response delayed beyond it. The regression still requires deadline failure, the same operation ID and exactly one request followed by one status query. No test is skipped; shipping runtime deadlines, polling and retry behavior are unchanged. The failed tag is not rewritten.

### Candidate verification

On the v0.3.1 candidate: TypeScript check; 56 Bun tests / 477 expectations; 588 native tests (including the isolated FIFO child, with one ignored test); 29 coordinator tests; release build/package; shell syntax and stable-note/version validation passed. The packaged app and helper passed strict signature verification, both advertised updater protocol 2, and JIT entitlement was present only on `rig-decode-worker`.

The actual packaged app started in an isolated existing profile, reported ready UI/control, accepted Herdr registration and `app_version: 0.3.1`, returned the built-in Rubelia dialogue target, retained English preferences and stopped normally. This is programmatic runtime proof, not physical keyboard/IME, official signing/notarization or a completed user Homebrew upgrade.

### Upgrade and limits

Follow [0.3 upgrade guidance](0.3.md#upgrade-from-v021-or-beta). Stop the old daemon and back up the actual config and state directories before replacing its binary. Retain imported characters, preferences and saved dialogue; in-memory drafts do not survive restart. Protocol-1 updater records are not automatically migrated or replayed. Check both CLI `--version` and the restarted daemon's `app_version`/executable. Stable Homebrew availability depends on the separately updated formula and published assets, not this source note. The macOS arm64 package uses ad-hoc signing, not notarization or an official Developer ID signature.

## 한국어

v0.3.1은 통합된 0.3 계열의 안정판 소스·기본/사전 빌드 대상입니다. 실제 출시는 비초안·비프리릴리스 GitHub Release와 arm64 압축 파일·개별 체크섬·`SHA256SUMS`의 완전한 게시로 판단합니다. 소스 버전·태그만으로 바이너리 게시를 주장하지 않습니다.

세션 검색·상태 필터·정렬·실행 중 우선, 네이티브 자동화 CLI, 충돌 인식 대사 초안, 8방향 말풍선 크기·문맥 설정·독립 표시, 공식 캐릭터 브라우저의 명시적 검증 다운로드·적용, 설치 출처별 protocol-2 업데이트·복구와 worker 전용 JIT를 포함합니다. v0.2.1 Arin 호환성을 유지하며 확인만으로 설치·재시작·베타 전환·Git 갱신을 하지 않습니다. 자세한 기능과 이전 소스 검증 범위는 [동결된 v0.3.0 소스 노트](v0.3.0.md)를 참고하세요.

v0.3.0의 Release workflow는 180ms deadline fixture에서 두 번 실패해 자산을 게시하지 못했고 태그만 보존됩니다. v0.3.1은 테스트에 즉시 Pending 응답·2초 poll 여유·그 이후 terminal 응답을 주어 CI 스케줄링 가정을 수정합니다. deadline 실패, 같은 operation ID, request 한 번·status 한 번 검증은 유지하며 테스트를 건너뛰거나 실제 앱의 deadline·poll·재시도 동작을 바꾸지 않습니다. 기존 태그를 덮어쓰지 않습니다.

[한영 이전 안내](0.3.md#한국어--v03-계열)에 따라 기존 데몬을 먼저 종료하고 실제 설정·상태를 백업하세요. 가져온 캐릭터·설정·저장 대사는 유지하지만 메모리 초안은 재시작 후 유지되지 않습니다. 구형 protocol-1 기록은 자동 이전·재실행하지 않습니다. 재시작 후 CLI 버전뿐 아니라 데몬의 `app_version`과 실행 파일을 확인하세요. 안정판 Homebrew 포뮬러는 실제 자산 게시 후 별도 갱신하며 베타 포뮬러·기존 베타 자산·팩 v5·`default@0`·그림·라이선스는 유지합니다. 배포는 macOS arm64 ad-hoc 서명이며 공인 Developer ID 서명·notarization은 아닙니다.

v0.3.1 후보에서 TypeScript, Bun 56개·477 expectations, 네이티브 588개(FIFO 자식 포함·1개 ignored), coordinator 29개, release 빌드·패키징, 설치기 문법·버전/노트 검사가 통과했습니다. 앱·도우미 strict 서명과 protocol 2를 확인했으며 JIT 권한은 `rig-decode-worker`에만 있습니다. 실제 패키지 앱을 격리된 기존 프로필에서 실행해 UI/control ready·Herdr 등록·`app_version: 0.3.1`, 루벨리아 대사 대상·영어 설정 유지·정상 종료를 확인했습니다. 이는 프로그램 방식 런타임 증거이며 물리 입력·실제 IME·공인 서명·notarization·사용자 Homebrew 업그레이드 완료 인증은 아닙니다.
