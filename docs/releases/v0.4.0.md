## Consumer contract

- Herdr owns its `native-adapter`, plugin manifest, thin consumer wrappers, 21 existing action IDs, hooks, host patches, link instructions and OMP outcomes extension. Incoming guarded Plugin Manager backend and optional UI remain Herdr-owned; generic preference ownership/transport and common UI remain core-owned. The consumer requires a verified compatible native installation with `integration_api: 1`, not equal plugin/app versions.
- Discovery uses explicit absolute executable → validated account-home shared locator → native `desktop-pet` on PATH → actual Brew prefix → account-home `Applications/DesktopPet.app`. Invalid explicit selection/locator fails closed. Only absent installation permits bootstrap using the actual pinned, digest-verified core installer. Incompatible installations require explicit native upgrade/repair; no native build or silent fallback occurs here.
- The consumer resolves injected Herdr config/state paths, then explicit paths, then Herdr defaults, and passes both resolved absolute paths to core. Adapter-owned `--herdr-socket ABS` is separate from the pet's private control socket. Profiles and imported characters remain in place; no automatic move or merge.
- Plugin updates/removal affect this integration only, not the shared app, profile or characters. Normal native updates never reinstall the plugin. Optional attach auto-start still needs the integration-owned patch on official Herdr 0.9.3 or a real hook-capable host; plugin installation does not patch Herdr. `ensure` preserves saved provider/profile and hidden state.

Public installation and explicit start:

```sh
brew install hanbong5938/tap/desktop-pet
herdr plugin install hanbong5938/herdr-desktop-pet
herdr plugin action invoke start --plugin desktop-pet
```
