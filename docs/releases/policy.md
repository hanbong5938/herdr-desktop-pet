# Versioning and compatibility

[Versions](README.md) · [한국어 버전 안내](README.ko.md) · [Publishing](publishing.md)

## A commit is not a release

The v0.3.1 manifests identify the **stable source and default/prebuilt target**. Its [reviewed bilingual note](v0.3.1.md) and [0.3 upgrade guidance](0.3.md) describe the integrated change from the separately preserved public v0.2.1 patch. `--source` builds the checkout in hand; a successful v0.3.1 default/`--prebuilt` installation depends on the exact non-draft Release, complete assets and installer cutover. A source commit or note alone does not prove that an archive/formula has been published or an old daemon restarted into the new executable. Check actual Release assets and `status`/executable after stopping the older daemon.

A tag alone is also not a published binary release. v0.1.5 is a historical example: packaging failed before assets were published. v0.3.0 is also tag-only: the native deadline fixture failed twice before asset publication; its immutable source note is retained and v0.3.1 repairs the fixture. The generated Wiki determines public release status from the GitHub catalog: a stable, non-draft release must have an actual publication timestamp and all required nonempty, uploaded app archive/checksum assets. A note file, a draft, or partial assets are not a substitute.

## Pre-1.0 version choices

- **Patch (`0.Y.Z`)**: contract-preserving fixes. Correct an implementation or distributed asset while retaining the documented capability, behavior, compatibility, and consumer-safety contract.
- **Minor (`0.Y.0`)**: capability additions, intended behavior changes, or compatibility changes while the app is below 1.0. Describe the old and new contract and provide migration guidance for affected consumers; a pre-1.0 version is not permission to leave changes unexplained.
- Evaluate the actual change, not its size or the name of the affected file. A fix that changes a documented consumer contract needs the minor-change treatment rather than being hidden as a patch.

These are forward-looking release decisions, not a claim that historical releases already followed this policy. The [0.1 overview](0.1.md) records earlier changes, including the v0.1.4 → v0.1.6 reply transition.

## Keep compatibility dimensions separate

| Dimension | Meaning and authority |
| --- | --- |
| Desktop app version | App behavior and its packaged binary; these manifests select v0.3.1 stable source/default-prebuilt target, while public availability is determined by the live Release catalog and uploaded assets. See the [v0.3.1 note](v0.3.1.md), prior [v0.2.1 patch](v0.2.1.md), and root [runtime guide](../../readme.md). |
| Herdr host version and capabilities | Independent host implementation. Local observation has a 0.9.0+ baseline; remote observation needs compatible saved-machine forwarding and server support; `agent.prompt` needs actual server method support. Client-attach auto-start requires official 0.9.3 source with the supplied patch applied and built, or a future actual host release advertising that hook. Stock 0.9.0/0.9.3 do not provide `client.attached`. A manifest minimum does not prove compatibility. See the [integration guide](../../integrations/herdr/README.md). |
| Character pack format | **v5** is the character-pack format, not the app version or a Herdr host release. Existing authoring/pack guides and validation rules remain authoritative; app documentation does not silently change this format. |
| Bundled default identity | **`default@0`** identifies the built-in Rubelia default. Artwork corrections do not by themselves imply a new app compatibility level, pack-format version, or imported-character selection. Existing artwork licenses, attribution, source records, and approval evidence remain authoritative. |

An app release does not release Herdr, install a patched host, guarantee a host API method, or relicense artwork. The installation/runtime authority stays in the bilingual root [English](../../readme.md) / [Korean](../../readme.ko.md) guides. This policy is not a second installation guide.

Remote observation remains read-only; prompt submission is scoped to an eligible selected local session. Herdr acknowledgement is not agent completion. Compatibility and upgrade notes must preserve those distinctions, IME/send safety, lifecycle settings, and persistence limits rather than reducing them to a version-number table.

## One reviewed source, two publication views

For a **new stable** release, `docs/releases/vX.Y.Z.md` is reviewed in the main repository before tagging. Its first heading is exactly `# Herdr Desktop Pet vX.Y.Z release notes`. The release tag freezes that note. The new GitHub Release body and generated Wiki version page use the same tagged source; repository-relative links in Release bodies resolve to that exact tag, while Wiki links resolve to generated pages or explicit source links. Version notes do not maintain a second handwritten release date; GitHub's release catalog owns publication state and timestamp. The v0.2.0 canonical [stable note](v0.2.0.md) is distinct from the published beta2 and beta3 canonical notes frozen in their respective isolated prerelease snapshots. Those beta tags and assets stay immutable; beta3 did not trigger the stable `v*` Release/Wiki workflows.

The v0.2.1 note and Release body remain frozen at the isolated public-v0.2.0-based patch tag; that historical scope did not authorize promoting unrelated features *as part of the patch*. The separately authorized v0.3.1 minor source includes those integrated changes and needs its own reviewed tag-frozen note, combined gates and publication. Current Wiki navigation uses reviewed default-branch documents, whereas the v0.3.1 version page and Release body must come from its exact tag once published.

The Wiki's navigation and status use the current release catalog, not the catalog as it might have looked at an old tag. Unreleased and current navigation use reviewed default-branch documentation. The earlier documentation/tools-only authorization applied to the old `9cbad32`-era main change, not to the now-authorized native v0.2.0 stable promotion and Wiki publication. See [Publishing](publishing.md) for generation and publication details.

### Historical documentation exception

The initial v0.1.4–v0.1.11 tags predate the canonical release-note tree. Their pages are reconstructed in reviewed current source from contemporaneous evidence, with provenance and links to the original tags and actual Releases. v0.1.5 has a source tag but no binary download. Generating these historical pages does not retag, replace archives, or rewrite old Release bodies. For future releases whose tagged notes exist, use the frozen tagged content instead of silently replacing it with later edits.

Historical test counts, native probes, and limitations remain reported evidence with their original scope. They are not newly executed verification, and a source probe is not proof of publication, physical keyboard IME behavior, or OS-granted focus transfer.

## Release lines are navigation, not support promises

Each minor line has an `X.Y.md` overview and individual `vX.Y.Z.md` notes; add a new line to the bilingual versions index when it exists. Migration guides explain consumer-visible transitions. Keeping an old release link available is not a promise of backports, ongoing testing, a maintenance window, LTS, or an EOL date. No LTS/EOL guarantees or invented support labels are introduced here.

## 한국어 핵심 원칙

현재 매니페스트는 **v0.3.1 안정판 소스·기본/사전 빌드 대상**을 나타내며 게시 여부는 실제 자산으로 판단합니다. 공개 v0.2.1은 v0.2.0 기반 Arin 참조 전용 mesh 호환성 패치로 별도 보존합니다(앱 v0.2.1 이상 필요). 새 [v0.3.1 노트](v0.3.1.md)·[한영 이전 안내](0.3.md)는 검색·정렬·자동화·초안·말풍선 크기·공식 팩 브라우저·protocol-2 업데이트·worker JIT 개선을 새 minor로 설명합니다. 기본/`--prebuilt`의 v0.3.1 성공 설치는 실제 비초안 Release·완전한 자산·갱신된 설치기로 확인하며 기존 데몬 종료 후 `status`의 실행 파일·버전을 점검하세요. v5·`default@0`·원화·라이선스·이전 릴리스는 유지합니다.

원래 `9cbad32` 시기에는 공개 `main`·안정판이 v0.1.11이었지만 그 문서·도구 전용 제한은 이후 네이티브 v0.2.0 안정판 승격 허가가 아닙니다. 독립 표시·메뉴 막대 모드/이미지·연결 워크트리 삭제는 1.0 이전 minor 기준에 해당합니다. 게시된 `beta/0.2.0-beta.1` 태그와 동결 소스 `6749439657f73ea6882b769f4a9968f637f8d6d4`의 검사는 **beta1 전용**입니다. 별도 게시된 beta2는 동결 소스 `9035c11e5acf76a1092ddf3a08d4360eac680495`의 `beta/0.2.0-beta.2`이며 입력창 잘림·Markdown 스캐너 수정까지 포함합니다. 세 자산의 익명 HTTP 200·크기·SHA-256·GitHub digest와 20,467,673바이트 압축파일의 SHA-256 `ddb61fa2ff45aa0fcc603c175423667512b7fa043461b6ab5e9f2c37576a6432`는 **beta2 전용**입니다. 당시 tap `cbdd3d9f001b6bc85422b53d74e52f35579318b0`의 beta1 → beta2 업그레이드·신규 설치 `brew test`도 beta2의 기록이지 안정판 0.2.0 검증이 아닙니다. 네 네이티브 그룹의 출발점 `bf23ced1649fd0074aec8736644c8f02aa0c492b`는 과거 로컬 구현 기록이며 v0.1.11 바이너리에는 없었지만 [v0.2.0](v0.2.0.md)에 승격됐습니다. patch는 기존 계약 보존 수정이고 minor는 기능·동작·호환성 변경 및 마이그레이션 안내에 사용합니다.

**beta3는 별도 게시된 역사적 시험 채널입니다.** 동결 소스 `7f644b10affba45957a52c361d2067439a4f1eeb`의 변경 불가 `beta/0.2.0-beta.3`은 draft가 아니고 latest도 아닌 prerelease로, beta2에 답장창 Command-A/C/X/V의 네이티브 전체 선택·복사·잘라내기·붙여넣기를 더합니다. 태그 이전에 확정된 공식 기록은 공개 Release 본문과 일치합니다. 격리 beta3 소스 TypeScript·Bun 44개(기대값 355개)·범위 rustfmt·네이티브 arm64 release 검사·빌드·테스트 343개(주 342개 + FIFO child 1개)와 실제 AppKit 입력창 배치 executable이 통과했습니다. 일회용 production `ComposerView`/`BubblePanel` 프로브는 사설 named pasteboard와 key equivalent·`sendEvent:`/`keyDown:`로 한글·이모지·CRLF, UTF-16 선택 대체, A/C/X/V, Caps Lock·포커스·추가 modifier·조합 보호를 확인했으며 사용자 클립보드를 건드리지 않았습니다. 이는 **안정판 0.2.0 시험, 물리적 키보드·실제 IME·선택 창/확인 창 키·포인터·VoiceOver 인증이나 영구 회귀 테스트가 아닙니다.** 공개 세 자산의 익명 다운로드와 크기·SHA-256·GitHub digest가 일치했고, 20,467,942바이트 `HerdrDesktopPet-v0.2.0-beta.3-macos-arm64.tar.gz` SHA-256은 `14bf452aa492fa520a4979ca3e18711e505c52c178c1e1e2edb355b2b07b0920`입니다. `.sha256`와 `SHA256SUMS`는 각각 115바이트(체크섬 파일 SHA-256 `60dba5f648065f20793e68cc2c0abea25cedaf34412b0bacf3b928e75e228e5f`)입니다. 당시 tap `2d6ec6a9ae3427367883a45e469cf3e82fe8f8dd`의 갱신형 베타 포뮬러는 별도 `HerdrDesktopPetBeta.app`/`herdr-desktop-pet-beta`를 설치했으며 beta2 → beta3 업그레이드·신규 설치의 `brew test`가 통과했습니다. 순정 Herdr 0.9.3은 `client.attached`가 없습니다. 안정판·베타는 프로필과 제어 네임스페이스를 공유하므로 기존 데몬을 종료·백업하고 병행 시 **설정과 상태를 모두** 격리하세요. 베타 태그·본문·자산은 안정판 승격으로 바뀌지 않습니다.

**과거 베타 준비 기록:** 앞선 `0.3.0-beta.1` 계획은 당시 검색·정렬 기능을 실제 GUI 수락 전에 준비한다는 문맥이며 공개 자산의 증거가 아닙니다. 별도 v0.3.1 안정판 소스가 그 이후 준비됐으며 출시 여부는 Release 목록으로 확인합니다. 기존 베타 태그·자산(`beta/0.3.0-beta.2` 포함)은 유지합니다.
