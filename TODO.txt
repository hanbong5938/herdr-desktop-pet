Herdr Desktop Pet 0.1.6; approved Rubelia redraw and inline replies
==========================================================

Requirements and distribution
- Apple Silicon macOS 13+. Local observation supports Herdr 0.9.0+;
  remote observation requires a compatible saved-machine forwarding CLI
  (documented in 0.9.2) and compatible remote server. Lifecycle client-attach
  auto-start REQUIRES official Herdr 0.9.3 source with
  integrations/herdr/client-attached.patch applied and built, or a future
  actual host release advertising that hook. Stock Herdr 0.9.0/0.9.3 do not
  implement client.attached. A manifest minimum version alone does not prove
  compatibility: inspect plugin-link warnings and verify subscription.
- Release 0.1.6 includes lifecycle settings, editable dialogue, status
  indicators, inline-card replies, and the approved new Rubelia default.
  Use bash scripts/install.sh --source to build local changes.
  Link against the running patched host (PATCHED_HERDR from the integration
  guide, not an installed herdr on PATH):
    "$PATCHED_HERDR" plugin link /absolute/path/to/checkout --enabled
    "$PATCHED_HERDR" plugin action invoke start --plugin desktop-pet
  Linking/enabling on an already-running server alone does not launch the pet;
  start once or wait for a subsequent shell/terminal attach with auto_start on.
  See integrations/herdr/README.md for a separate disposable patched-host
  XDG profile; do not replace an installed host or assume stable PATH is patched.
- Release v0.1.6 ships the approved new Rubelia ten-pose default.
  The prebuilt installer verifies checksum, archive layout/types, arm64,
  signature and default model. An optionless install may select the pinned
  prebuilt; use explicit --source to build local changes.
  Source builds require Rust, Bun, Node.js/npm and Xcode Command Line Tools.
  Running prebuilt needs no build toolchain.
- Rubelia is the only bundled character and default model (default@0).
  User-imported PNG and rig packs remain supported. Optional Aurora,
  Coding Cat and Rubelia outfits live in herdr-characters, not this bundle.
- Releases: https://github.com/hanbong5938/herdr-desktop-pet/releases
- The primary repository is public. Homebrew needs no GitHub login; the
  --prebuilt download script uses authenticated gh.
- Rubelia retains the owner's shared-world-canon identity and default@0.
  The 2026-10-02 approved drawing now supplies waiting/style authority; nine
  other complete poses are fresh local Qwen drawings, each with own layered
  PSD, eye/mouth shapes and complete native phase/reaction motion. Two poses
  use disclosed pre-export upper-thigh source framing; raw/master art remains.
  The thumbnail is a genuine native waiting capture. Source/owner/model
  records travel with the pack; software MIT does not relicense artwork.
  v0.1.6 includes this redraw; older releases and imported selections remain.
- App bundles are ad-hoc signed, not Developer ID signed or notarized.
  macOS may require explicit approval to open the app.
- Native hit-overlay blending uses typed subexpressions for compatibility with
  the release runner's Xcode 16.4 Swift compiler.

Inline interaction changes included in v0.1.6
- Replace the always-visible multiline composer with on-demand, single-line
  replies under the selected session card; keep session drafts and send safety.
- Preserve composing text while deferring card selection, filter changes, and
  row replacement; replay only the latest valid, visible target after composition.
- Reflow reply controls from the final card width and invalidate bubble content
  on reply close, independent of whether a frame tick or wake consumes the ACK.
- Refine inline reply controls with an opaque palette-derived input fill and a
  compact native action button; preserve geometry, IME, drafts, and send behavior.
- Normalize line breaks in every committed reply input, including direct
  typing, paste and text import, to spaces; do not alter active IME preedit.
- Keep the reply attached to the final selected displayed row after row
  insertion or deletion. During composition, resolve displayed session keys
  from retained records independently of the filter and display cap; update
  live status and localized Korean/English hints with submission disabled.

Controls
- Use the menu-bar icon for character selection and dialogue editing, observation
  sources, bubble and lifecycle settings, and language. Local observation is on
  by default; Remote is opt-in.
- Tap the head/body for reactions; move back and forth on the head to pet it.
- Drag the body/background to move; Option-drag anywhere also moves.
- Use the bottom-right grip to resize.
- Full-window click-through ignores both pet and bubble windows, disabling
  inline reply interaction too.
- Alpha click-through lets clicks pass through transparent artwork regions.
  It uses pointer polling, so leave it off if a click-routing race is unacceptable.
- The bubble shows observed Herdr session status, not inferred provider results.
- Expand the bubble to see cards. Source build only: the one-line reply is
  initially hidden, including in All. Click a local agent session card to open
  its inline reply; choosing another card folds the old field and opens the
  new one. Remote cards show read-only feedback, with no reply or Send
  control. Enter, Command+Enter,
  or Send submits; IME composition does not submit. Escape cancels active IME
  composition first, otherwise it folds only the reply field. Clicking outside
  the bubble also folds only the field, except during IME composition; clicking
  elsewhere inside the bubble does not automatically fold it. Selection, filter,
  and row replacement wait for composition to end, with live status and send
  eligibility still current. Per-session drafts live in memory through folding
  or bubble collapse, not app restart. Success
  clears and folds only the matching current reply; an edited draft or a newly
  selected field survives an in-flight send. Failure or uncertain delivery
  preserves the draft and field state. Acknowledged submission is not completed
  agent processing.
- Submission uses only the selected local source's agent.prompt API, not a
  global CLI, shell, SSH, or raw pane input. Excluded local sources, offline,
  stale, unready, and unsupported targets cannot receive prompts; retained
  remote rows cannot send either. unsupported_method is reported without
  fallback. Approvals/questions need the real terminal. The API was verified
  with Herdr 0.9.2; the 0.9.0 local observation baseline does not
  guarantee agent.prompt support on the running server. Unknown delivery must
  be checked before resending; there is no automatic retry. The current API
  addresses the agent currently occupying a pane with no atomic expected-
  session guard: instantaneous occupant/session replacement cannot be ruled
  out.

Custom dialogue
- Open the separate resizable Dialogue window from the Characters tab; choose
  inactive characters and historical revisions without renderer activation.
  Select Korean/English and one of eight sidebar events: idle/running/waiting/
  unknown/head tap/body tap/pet/observed task completion. Unsaved event badges
  identify drafts; without an override, the original pre-fills the editable
  field and is also available as a collapsible reference.
- Save one language/event entry with Save dialogue or Command+S, multiline and
  at most 2048 UTF-8 bytes. Blank/whitespace-only text removes that override.
  Successful saves refresh applicable bubbles for the active character ID, even
  when editing its historical revision; inactive edits do not activate the renderer.
- Reset this entry confirms loss of a dirty draft. Reset all character dialogue
  always confirms removal of that character's Korean and English overrides.
  Missing entries keep existing dialogue fallbacks.
- Character/language/event drafts survive context changes and closing/reopening
  the editor during this app session; only saved entries survive restart.
  Command+Z/Shift+Command+Z undo/redo within the current editing context.
  Failed saves retain the draft and committed dialogue.
- preferences.json stores personal dialogue separately from pack files, keyed
  by character ID and shared across revisions. External --assets paths use a
  separate canonical-path namespace, isolated from the bundled character.
  The active external character remains editable under its activation-time
  canonical identity if its source folder is renamed while running; restarting
  with a changed --assets path does not migrate the original persisted path key.
- Editing language does not change UI language. Custom text does not alter
  session counts, state transitions, reaction timing or disconnected-host notices.

Observation sources
- Local is on and Remote is off by default. Opt into Remote under the menu-bar
  settings, then select enabled saved machine profiles. Each profile observes
  its saved remote Herdr session, not every session on its host; session cards
  identify the Local source or the machine name. Remote observation needs a
  compatible remote Herdr server and local CLI with saved-machine API forwarding
  (documented in Herdr 0.9.2), not just the 0.9.0 local observation baseline.
- Set up SSH and add/authenticate saved machines in an interactive Herdr
  terminal; the remote host does not need the pet app/plugin. Selected profiles
  are polled about every 5 seconds; short transitions may be missed. Machine
  selections persist when Remote is off or profiles are renamed. Disabled or
  removed profiles stop contributing without stopping remote processes; all
  sources off shows Unknown. Disconnected cards reflect last known data, not
  live state. After recovery/reselection, the first snapshot is a baseline,
  not a replay of old completion reactions.
- For SSH authentication recovery, use herdr machine reconnect '<profile-id>'
  in a terminal. The pet does not run interactive setup or use Local as a
  fallback for remote errors. Remote sources are observation-only; prompts
  are never sent through machine forwarding.

  isolated profile with a real Unix-socket fixture exercised direct Cocoa

  Native regression suite: 275 passed.

Lifecycle settings and plugin actions
- Settings tab: independent auto_start (auto-launch on server startup and
  successful shell/terminal client attach) and exit_with_herdr (quit after
  last healthy server connection disappears). New profiles default on/on.
  Existing lifecycle.json profiles migrate boolean enabled to auto_start,
  retaining false; absent exit_with_herdr defaults off for existing profiles.
  lifecycle.json exclusively owns both settings; preferences.json does not.
  Preserve endpoints/startup/other fields. Invalid JSON/types/keys/values
  report errors instead of silently resetting. Failed saves retain prior
  switch states and live policy and display an error.
- With auto_start off, automatic ensure successfully skips absent pets and
  can register a server for one already running. Manual start works without
  changing either setting. Stop/Quit terminate only this run or pending
  startup, not auto_start; restart manually relaunches, preserving settings.
  When auto_start stays on, later qualifying startup/attach can relaunch.
  Plugin disable/unlink is a separate host feature; disabled plugins cannot
  run hooks/actions. Confirmed disable across all registered endpoints ends
  an already-running pet immediately.
- With exit_with_herdr on, initial server absence or loss of the last
  healthy server starts a 30-second grace; healthy reconnection cancels it.
  One remaining healthy server prevents exit. Client detach is not server
  loss; stale endpoints and failed retries never extend grace. Switching
  exit off cancels a live countdown; switching it on while disconnected
  starts a fresh 30 seconds. Off permits independent manual running.
  Existing hidden pet stays hidden on ensure. Changing auto_start never
  forces the current pet to stop/show; show/hide/toggle affect visibility
  only. Restart preserves position, scale and preferences.
  herdr plugin action invoke status --plugin desktop-pet
  herdr plugin action invoke settings --plugin desktop-pet
  herdr plugin action invoke restart --plugin desktop-pet
  herdr plugin action invoke stop --plugin desktop-pet
- Global settings action opens just the lifecycle window with the pet
  stopped, but requires a live, enabled Herdr host. The direct native CLI
  works with pet stopped, host absent, or plugin disabled, without launching
  a pet. Run this source build's executable directly:
  PET=./dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet
  "$PET" settings
  "$PET" settings get
  "$PET" settings set auto_start off
  "$PET" settings set exit_with_herdr on
  get/set output structured JSON. set accepts only exact keys
  auto_start|exit_with_herdr and values on|off; invalid arguments and save
  failures error. status includes auto_start and exit_with_herdr.

Character packs
Use the Characters menu, or the native executable:
  dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet pack list
  dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet pack import --path PATH
  dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet pack select ID
  dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet pack select default
  dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet pack update ID --path PATH
  dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet pack restore ID --revision N
  dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet pack remove ID
  dist/HerdrDesktopPet.app/Contents/MacOS/herdr-desktop-pet pack status OPID

In the Characters tab, row/revision choices stage a candidate until explicit
Apply. Cancel selection clears an unsubmitted candidate; closing/reopening the
panel preserves it. Pending pack mutations block selection, Apply, Cancel,
Import, Update, Remove, and Restore; read-only inspection/diagnostics stay usable.
Picker/confirmation returns recheck busy work and the original listing generation.
Canceled/failed operations retain the candidate; unknown submitted results retain
their full operation ID in the footer tooltip and diagnostics for pack status.
Rejected submissions are distinct from unknown submitted operations. The latest
UI result survives Apply completion and fresh staging; inactive non-rendering
mutations show completed, not pending renderer apply. Live/committed selection
mismatches are separate warnings. Native CLI pack select/restore remain immediate
without UI Apply, and CLI queue/idempotency behavior is unchanged.

Import accepts a character directory or .herdrchar archive and does not select it.
Select uses the newest revision; restore selects an existing historic revision.
Removing an active pack returns to Rubelia. The built-in default@0 cannot
be imported, updated or removed. Preserve operation IDs: if an outcome is
uncertain, query pack status instead of blindly repeating the mutation.
If both registry files are corrupt, builtin original dialogue remains readable
at the current listing generation without activation or registry repair;
unavailable managed revisions remain unavailable.

Configuration
- HERDR_PLUGIN_CONFIG_DIR: lifecycle.json (sole lifecycle settings owner),
  preferences.json (other preferences), and characters/.
- HERDR_PLUGIN_STATE_DIR: process lock, control socket and daemon log.
- Without injected paths, use Herdr's XDG config/state plugin directories.
- Native commands accept --config-dir and --state-dir for an isolated profile.
- Use Herdr's upstream provider integrations; restart/reload existing provider
  sessions after installing their upstream lifecycle hooks.
